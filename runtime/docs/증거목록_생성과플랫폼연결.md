# 반출 증거 목록 생성과 플랫폼 연결

AWS에 접속하지 않고 로컬 반출본만 읽는다. 원본은 수정하지 않는다. 생성 목록은 과거 회차의 기록이며 현재 서버 상태나 운영 승인 성공의 증명이 아니다.

## 생성

저장소 루트가 `/home/bobgy/bobproject/byul`인 예:

```sh
cd /home/bobgy/bobproject/byul/runtime
# 최초 환경 준비 때 필요: jsonschema 의존성
uv sync --extra evidence
.venv/bin/python -B -m tools.evidence_index \
  --input run12="$HOME/.local/state/serving-runtime/aws-lab/evidence-20261108-run12.tgz" \
  --input run13="$HOME/.local/state/serving-runtime/aws-lab/evidence-20261108-run13.tgz" \
  --output /tmp/byul-evidence-run12-run13
```

출력은 `evidence-index.json`, `import-report.json`, `files/<run>/<원래 상대 경로>`이다. 계약의 `path`는 **`files/` 기준**이므로 `run12/ev/check-after-apply.json`처럼 기록한다. `files/` 접두어를 중복해서 넣지 않는다. 파일은 0600, 생성 폴더는 0700이다. 플랫폼은 같은 사용자로 실행한다.

- `--input RUN=PATH`를 반복한다. tgz와 폴더를 모두 받는다. RUN은 고정된 영문·숫자·밑줄·하이픈 식별자이다. 입력 순서와 무관하게 결과를 정렬한다.
- `run숫자` tgz는 `runtime/docs/AWS_GPU_서버숫자회차_결과_*.md`가 정확히 하나면 연결한다. `--result-doc RUN=문서경로`로 명시할 수도 있다. **반출본 파일명 언급 또는 해당 회차 제목**으로 문서와 입력의 관계를 확인한다. 제목의 회차가 다르면 `DOCUMENT_RUN_MISMATCH`로 중단한다. 관계가 확인된 문서에서는 계산한 **전체 64자리 해시가 어느 줄에든 있으면** 전체 대조 성공이다. 다른 전체 해시가 함께 있어도 일치 값이 있으면 성공하며, 다른 전체 해시만 있으면 `SHA256_MISMATCH`로 중단한다.
- 문서에 전체 해시가 없고 SHA-256으로 표시한 접두만 있으면 계산 해시의 접두와 대조한다. 반출본 언급 줄과 다음 줄을 먼저 보며, 그곳에 접두가 없으면 문서의 SHA-256 표시를 찾는다. 날짜나 commit 값 같은 일반적인 8자리 문자열은 해시 근거로 삼지 않는다. 접두만 일치하면 `hash_verified:"prefix_only"`이며 자동 등급은 `DECLARED`다. 불일치하면 중단한다.
- `--sha256 RUN=64자리해시`는 항상 계산 해시와 같아야 한다. 문서의 전체 해시가 없거나 해시 자체가 미기재여도 명시 근거로 진행한다. 다만 문서의 전체 해시 또는 접두가 계산 값과 불일치하는 것을 덮지 않는다. 문서가 있으면서 해시도 명시 인자도 없으면 `DOCUMENT_HASH_MISSING`이며, 문서 자체가 없는 입력은 기존처럼 `none` 근거로 가져올 수 있다.
- 폴더 SHA-256은 정렬한 `[상대경로, UTC 파일시각, bytes, 파일 SHA-256]` 배열의 정규 JSON(키 정렬·공백 없음·UTF-8·끝 LF) 해시다. **tgz 해시와 다르다.** 첫 보고서의 해시를 이후 `--sha256 RUN=...`에 고정할 수 있다. tgz 결과 문서 자동 연결은 폴더에 적용하지 않는다.
- 수집 시각은 tar member mtime 또는 원본 파일 mtime이다. 문서의 `환경·시간`에 날짜·KST 기동 요청·stopped 확인이 모두 있으면 `window`에 회차 구간(중지 확인까지)을 기록한다. 확인되지 않으면 null이다. `--window RUN=시간대있는시작,시간대있는종료`로 근거 있는 구간을 명시할 수 있다. `created_at`은 최신 원본 파일 시각으로 고정한다. 도구 실행 시각을 수집 시각으로 가장하지 않는다.
- 계약 enum은 `MEASURED / DECLARED / EXAMPLE`이다. **전체 해시가 일치하는 AWS GPU 서버 회차 결과 문서**가 연결되면 자동 `MEASURED`다. 시각 표기가 다른 과거 문서도 제목·입력 연관성과 전체 해시가 확인되면 인정하며, 회차 구간을 해석하지 못하면 window만 null이다. 실서버에서 수집한 파일이라는 의미이며 그 안의 후보·승인·미확인 사실을 전부 실측이나 운영 승인으로 바꾸는 의미가 아니다. 접두 근거만 있거나 근거 없는 입력은 `DECLARED`다. 사람이 근거를 확인하면 `--sha256 RUN=전체해시 --origin RUN=MEASURED`로 명시할 수 있고, 보고서에 `explicit` 근거와 `origin_assertion:"MEASURED"`를 남긴다. 전체 해시 대조 없이 MEASURED를 명시하면 `ORIGIN_REQUIRES_FULL_HASH`로 중단한다. 다른 수동 등급은 `--origin RUN=DECLARED|EXAMPLE`로 지정할 수 있다. 파일명이나 내용에서 합성·mock 출처 표시를 발견하면 더 보수적인 `EXAMPLE`로 내린다. 혼합 파일 전체도 `EXAMPLE`로 내린다.
- `collector`는 가져온 도구와 버전(`runtime-evidence-index / 1.1`)이다. `refs`에는 archive/folder-manifest와 결과 문서의 SHA-256 식별자를 둔다. 원래 사건과의 연관성을 임의 생성하지 않는다.
- stdout와 `import-report.json`에는 회차별 파일 수·제외 파일 수·고정 이유 코드별 건수·출처 등급별 건수·반출본 해시·대조 여부, `basis` 근거 목록, `origin_assertion`(수동 등급 또는 null)을 기록한다. 제외된 파일명·일치 비밀 값·원문은 출력하지 않는다. 한 파일에 여러 코드가 걸리면 코드 건수 합계가 제외 파일 수보다 클 수 있다.

| `basis` 값(여러 근거는 함께 기록) | `hash_verified` | 자동 등급 |
| --- | --- | --- |
| `document_full` | `true` | AWS 실서버 회차 문서면 MEASURED, 나머지는 DECLARED |
| `document_prefix`만 있음 | `"prefix_only"` | DECLARED |
| `explicit`(문서 전체 대조 없음) | `true` | DECLARED; 사람이 origin을 명시하면 그 주장을 기록 |
| `none` | `false` | DECLARED |

`hash_verified`의 `"prefix_only"`는 전체 대조 성공이 아니다. 보고서를 읽는 프로그램은 단순 truthiness가 아니라 값/근거 종류를 비교해야 한다. 합성 출처가 확인된 파일은 위 표보다 보수적인 EXAMPLE로 유지한다.

비밀 검사 코드: `TOKEN`, `TOKEN_ARGUMENT`, `BEARER`, `PRIVATE_KEY`, `AWS_ACCOUNT`(12자리 계정 형식), `INSTANCE_ID`, `ACCESS_KEY`, `JWT`, `SERVICE_TOKEN`. 내용과 파일명을 검사한다. null/none/false/true 및 명시적인 redacted 표시는 토큰 값으로 세지 않는다. 패턴 검사이므로 암호화·인코딩·알려지지 않은 비밀 형식의 부재까지 증명하지 않는다.

경로 이탈·심볼릭 링크·tar 하드 링크·장치/FIFO·sparse·중복 tar 경로는 전체 가져오기를 거부한다. tar를 `extractall`로 풀지 않고 허용한 regular member만 새 파일로 복사한다. 기본 상한은 파일 32 MiB, 입력 전체 파일 크기 합계 256 MiB, 전체 member(폴더 포함) 10,000개, tgz당 압축 크기 256 MiB다. 압축 해제 중 헤더·padding·후행 데이터에도 별도 상한을 적용한다. `--max-file-bytes`, `--max-total-bytes`, `--max-members`, `--max-archive-bytes`로 조정한다.

임시 폴더에서 계약(`byul-evidence-index/0.1`, producer runtime)과 date-time 형식을 자체 검증한 뒤 게시한다. 스키마는 로컬 `contracts/schemas`만 읽고 네트워크로 참조를 찾지 않는다. 같은 입력·메타데이터·옵션·문서·도구 버전의 재실행은 기존 출력 파일 내용과 대조한 뒤 **다시 쓰지 않고** 성공한다. 다른 출력이 이미 있으면 `OUTPUT_EXISTS_DIFFERENT`로 중단하므로 새 출력 폴더를 사용한다. 자동 덮어쓰기·삭제는 하지 않는다.

## 플랫폼 실행

```sh
cd /home/bobgy/bobproject/byul/platform/api
EVIDENCE_INDEX_PATHS=/tmp/byul-evidence-run12-run13/evidence-index.json \
  uv run byul-platform

# 목록 여러 개: OS 경로 구분자(리눅스 ':')
EVIDENCE_INDEX_PATHS=/tmp/run12/evidence-index.json:/tmp/run13/evidence-index.json \
  uv run byul-platform

# 로컬 모의 엔진과 함께 실행하는 기존 개발 스크립트도 환경변수를 전달한다.
cd /home/bobgy/bobproject/byul
EVIDENCE_INDEX_PATHS=/tmp/byul-evidence-run12-run13/evidence-index.json \
  platform/scripts/run-with-runtime.sh
```

마지막 스크립트는 로컬 Gateway·모의 엔진을 기동한다. 이 작업의 반출본 검증에서는 실행하지 않았다. 연결된 실제 runtime이 필요하면 첫 API 실행 예에 별도 `RUNTIME_BASE_URL`을 지정한다.

`EVIDENCE_INDEX_PATHS`를 지정하면 evidence 출처는 `file`이고, 생략하면 여전히 계약 예시다. runtime/update/store 출처가 예시이면 첫 화면과 내부 화면 모두 그 **출처 이름만** 예시 배너에 나열한다. `file` 연결 자체가 모든 항목의 실측을 뜻하지 않으므로 개별 `EXAMPLE` 배지는 유지한다.

플랫폼은 목록당 32 MiB로 읽기를 제한하고 여러 목록을 순서대로 읽는다. 동일 경로 중복 설정은 한 번만 읽는다. 헤더 한 번·항목 한 번씩 계약 검사하며, 실제 파일 출처에서는 index 옆 `files/` 아래에 regular file이 있어야 한다. 절대경로·상위 이동·빈 경로 요소·링크·폴더/특수 파일은 형식 오류로 남긴다. 목록 조회는 payload를 읽거나 다시 해시하지 않는다. 전체 API 응답은 여전히 모든 항목을 담으므로 여러 거대 목록의 응답 크기까지 제한하거나 페이지를 나누지는 않는다.

## 웹/플랫폼 예시 표시 점검표

점검 범위: `platform/web/src`, `platform/api/src` 전체의 `예시`, `합성`, `EXAMPLE`, `example` 관련 표시·생산 경로. 생성 타입·테스트 fixture·문서의 예시 설명은 제품 표시와 구분해 유지했다.

| 위치 | 표시·조건 | 실제 자료 연결 시 처리 |
| --- | --- | --- |
| `web/src/pages/LandingPage.tsx`, `components/SourceExampleBanner.tsx` | 첫 화면 고정 "일부 수집원은 합성" | **수정**: meta의 예시 출처 이름만 표시, 예시 출처 없으면 숨김 |
| `web/src/app/Layout.tsx` | 내부 화면 예시 배너, 상단 "일부 예시 포함", 연결 상태·사이드바 출처 | 기존 출처별 조건 유지, 배너만 공통 컴포넌트로 통일 |
| `web/src/components/Badges.tsx`, `lib/labels.ts` | `EXAMPLE` → "예시", unofficial `EXAMPLE_DATA` | 자료 등급/사유에 따른 정직한 표시 유지 |
