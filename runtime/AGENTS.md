# Codex 작업 지침

- 이 저장소는 신가영의 런타임 개발 작업 공간이다. 사용자가 요청하면 Claude가 작업을 정리하고, Codex는 구현·수정·시험, Claude는 대화형 세션의 직접 검수와 최종 보고를 맡는다.
- 공통 프로젝트 맥락과 문서 안내는 루트 `CLAUDE.md`를 읽어 확인한다. 그 파일의 Claude 검수 규칙은 Claude에 적용된다.
- 사용자 작성 개발계획서 v1.4(문서 상태: 개발 기준 설계안)가 전달됐고 직접 개발할 모듈은 Python을 사용한다. 연동 규격·실제 환경 등 남은 결정이 있다. 현재 요청받은 작업 범위에서 진행하며, 사용자 요청 없이 계획서 작성·기술 스택 확정·기능 구현을 시작하지 않는다.
- 구현을 맡으면 선택된 기능과 완료 기준에 맞춰 작업하고, 필요한 시험을 실행해 실제 결과와 미확인을 구분한다.
- 시험·설치·파일 기록이 필요한 작업은 처음부터 쓰기 가능한 Codex 스레드에서 시작한다.
- 시험에서 임시 디렉터리 권한 오류가 나면 실행 환경을 확인하고, `/dev/shm`이 쓰기 가능할 때만 `TMPDIR=/dev/shm`으로 재시도하며 모든 환경의 필수 설정으로 단정하지 않는다.
- Claude의 지적은 코드·요구사항·재현 근거로 확인한다. 타당한 문제를 수정·재시험하고, 동의하지 않는 지적은 근거를 설명한다.
- 수정·재시험은 필수 지적 위주로 하고, 선택적 문구 개선만으로 검수 반복이나 범위 확대를 하지 않는다. 커밋·푸시는 사용자의 요청 범위를 따른다.
- 검수 인계 시 변경 범위·새 파일·시험 명령과 결과·남은 제약을 짧게 정리한다. 이번 작업의 Git 기준점과 커밋 여부도 밝혀 검수 범위를 식별하게 하고, Claude의 대화형 검수를 기다린다.
- 실질적인 진행 후 `project-context/STATUS.md`를 갱신한다. 상세 로그와 긴 대화는 지침 파일에 누적하지 않는다.

## 목표·대상·판정 기준의 임의 변경 금지 — 사용자 지정, 2026-11-14

- 작업을 시작하거나 재개할 때 사용자의 원래 목표, 실제 작업 대상, 기준 판본·환경, 합격 기준, 승인 범위를 확인한다. 실행 편의나 중간 단계의 성공을 원래 목표보다 앞세우지 않는다.
- 대상은 원래 요구사항·실행 기록 등 독립적인 근거와 대조한다. 접속 성공, 이름·태그의 유사성, 처음 선택한 대상을 계속 같은 대상으로 고정한 것만으로 올바른 대상이라고 판단하지 않는다. 실제 환경 작업은 연결 계정·프로필·자원과 원래 시험 환경의 관계를 확인한 뒤 진행한다.
- 관측 결과가 핵심 전제와 충돌하면 관련 설치·수정·기동 등 상태를 바꾸는 실행을 멈추고 전제부터 검증한다. 예상한 파일·서비스·데이터가 없다는 이유로 새로 만들거나 다른 환경으로 대체해 모순을 덮지 않는다. 이미 확인한 근거와 미확인 사항을 구분해 알린다.
- 막힌 원인이 절차상의 오류인지, 대상·전제·범위의 불일치인지 먼저 구분한다. 원래 목표와 승인 범위를 유지하는 통상적인 절차 수정은 진행할 수 있다. 목표·대상·기준 환경·합격 기준을 바꾸거나 기존 배포를 다른 용도로 전환해야 하는 우회는 변경 이유와 영향을 제시하고 사용자 결정 전에는 실행하지 않는다. 방법을 알아서 판단하라는 위임도 이런 변경의 승인이 아니다.
- 새 보조 도구를 만들거나 수정 범위·반복 실행을 늘리기 전에, 그 조치가 원래 질문에 답하는 증거를 만드는지 점검한다. 준비 자동화 자체의 완성이나 오류 제거를 위해 원래 전제를 바꾸지 않는다. 모순이 이어지면 도구를 덧붙이기 전에 대상 선정과 실행 계획을 재검토한다.
- 과거 환경의 재현을 다른 서버의 최초 설치로, 실제 환경 확인을 모의 시험으로, 전체 검증을 일부 통과로 대체하지 않는다. 다른 검증이 필요하면 별도 목적·범위·결과로 명시하고 사용자가 선택하게 한다.
- 진행·완료 보고는 원래 목표를 기준으로 한다. 준비, 접속, 기동, 실제 시험, 합격을 구분하고 실행하지 못한 항목은 미실시로 남긴다. 자신의 선택을 정당화하려고 사후에 목적이나 합격 기준을 바꾸지 않는다.
- 사용자가 중단을 지시하면 기존 승인이나 이전 진행 계획을 근거로 재개하지 않는다. 바뀐 대상에 이전 승인을 자동으로 적용하지 않고, 해당 대상과 범위의 새 지시를 확인한다.
