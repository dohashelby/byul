# 시험 전 1차 확정 기준 — 2026-10-25

상태: **시험 전 1차 확정 — 2026-10-25.** 프레임워크 문서·양식을 개발·평가의 공통 기준으로 사용한다. 실제 시험·조직 정책 채택·배포 승인은 적용 단계에서 기록한다.

## 1. 기준선의 범위

정본 01–05, `data/checklist.json`, `data/environment_template.json`, `data/result_template.json`을 기준으로 삼는다. 로컬 공유용 01–07은 설명 자료, 개발 전달 폼은 구현 명세, 엔진별 검토와 평가 기록은 해당 범위의 근거다. 확정 당시 원문과 SHA-256은 [2026-10-25 고정 판본](https://github.com/mg-princess/serving-security-framework/tree/0ec5fb5fa5633b0817468b27684690a66fc7b4f5) 및 [기준선 판본 목록](data/pretest_baseline_20261025.json)에서 확인한다. 현재 문서의 설명·표기 정리는 Git 커밋으로 추적한다. 체크리스트는 8개 기능·36개 요구·77개 CHK·112개 분기를 유지한다.

## 2. 적용할 공통 절차

- 변경 근거 → 실제 자산·경계·보호 조건의 영향 → 관련 요구·CHK·분기 → 시험·재사용 범위 → 미결 사항·담당을 [05 §2.3](05_평가와_증거관리.md#update-impact-handoff)에 따라 기록한다.
- 결과의 분기 참조에는 기존 `apply_when` 원문을 보존한다. 실제 시험 조건·관측값은 케이스·증거 필드에 기록한다. [05 §6.5](05_평가와_증거관리.md#result-record-template)를 따른다.
- 과거 결과는 유일한 분기 대응을 확인한 경우에만 연결 기록을 추가한다.

상황별로 다음 단계에 넘길 정보와 재확인할 상태를 정한다.

| 상황 | 다음 단계에 넘길 내용 | 유지할 상태·재확인 |
| --- | --- | --- |
| 일반 업데이트 | 고정된 현재·후보와 변경 근거, 실제 사용·보호 조건 영향, 관련 시험 및 재사용 이유 | 정책·환경 유효성을 확인하고 기존 보호 유지 시험을 포함 |
| 근거 부족 | 영향을 판단하지 못한 변경, 필요한 자료·확인 담당, 확인된 범위의 시험 | 선정 목록을 바꿀 미결 사항이 있으면 목록 미완결. 자료 확보 후 선정·재사용 재검토 |

## 5. 적용·시험에서 확인할 범위

실제 엔진 실행, 계측 가능성, 평가자 판정 일치, 보호 효과와 사용 부담을 확인한다. SGLang의 소스 검토 범위·세션·지속 KV 적용 공백, TensorRT-LLM 미완료 범위와 R10 전체·R14의 평가 대기 상태는 각 적용 기록을 따른다. 조직 정책·승인·측정값은 실제 적용 결과로 남긴다.

## 6. 확정 이후 변경 관리

새 접점을 기존 요구로 표현할 수 없거나, 충분한 증거에도 판정이 모호하거나, 정상·위반의 오판이 재현되거나, 신뢰 가정·근거가 바뀌면 해당 부분을 개정한다. 편의 개선과 수집기 미지원은 개발 과제로 구분한다. 새 판본에서도 과거 결과와 당시 기준을 보존한다.
