# 런타임 셸 실행 차단 검증

2026년 11월 17일 AWS GPU 랩에서 vLLM 엔진을 대상으로 검증했다. 아래는 **시연에서 확인한 다섯 장면**과 **같은 엔진 Pod에서 별도로 진행한 세 차례의 반복 검증**이다.

## 시연 결과

시연은 vLLM 0.30.0과 Phi-3 Vision 기반 멀티모달 모델을 사용했다. 01~04는 같은 공격 코드를 대상으로 각기 요청을 보냈다. 01과 02는 동일한 요청 본문을 사용했다.

| 장면 | 관측 결과 | 확인 근거 |
| --- | --- | --- |
| 01 보호 전 공격 실행 | 엔진에서 시험용 셸이 실행됐고 추론 응답은 HTTP 200이었다. | 요청 직후 엔진 컨테이너의 실시간 로그에 `uid=` 출력이 나타났다. |
| 02 Gateway 요청 차단 | BYUL Gateway가 엔진에 전달하기 전에 요청을 거부했다. | HTTP 400과 `CODE_SELECTION_FIELD`. 대시보드 요청 상세에도 같은 판정이 표시됐다. |
| 03 셸 실행 차단 | 요청은 엔진에 도달했고 BYUL의 실행 정책이 지정 셸의 실행을 거부했다. | 엔진 로그의 `PermissionError: [Errno 1] Operation not permitted`와 같은 Pod·시도 구간의 Tetragon 이벤트. 이 이미지에서는 `/bin/sh`가 `/usr/bin/dash`로 해석되어 Tetragon에 기록됐다. |
| 04 직통 접근 차단 | BYUL 네트워크 정책이 시험 워크로드에서 엔진으로 가는 연결을 차단했다. | 시험 클라이언트의 연결 실패와 해당 통신의 Hubble `DROPPED` / `POLICY_DENIED` 기록. |
| 05 정상 추론 유지 | Gateway를 통한 정상 요청이 성공했다. | HTTP 200과 실제 생성 답변 `Ready`. |

## 별도 실환경 반복 검증

단일 노드의 단일 vLLM 엔진을 `monitor` 모드로 기동했다. Ready 이후 600초 관찰과 기동 중 호출의 승인 대조를 마쳤고, 정책·증거·커널 기능·관찰 기간·수집 상태·허용 모드 검사를 모두 통과한 뒤 같은 Pod에서 정책만 `enforce`로 전환했다.

BYUL의 `runtime-tg-exec-01` 정책은 Tetragon 1.7.1의 BPF LSM `bprm_check_security`에서 지정 셸 경로의 실행을 거부한다. 판정에는 실제 프로세스 오류, 시도와 연결된 Tetragon 이벤트, 전후 정상 추론, Pod 유지 여부를 함께 사용했다.

| 회차 | 시도 전 추론 | 실행 시도 | Tetragon 기록 | 시도 후 추론 |
| --- | --- | --- | --- | --- |
| 1 | HTTP 200 | EPERM (`errno 1`) | 같은 Pod·시도 구간에서 확인 | HTTP 200 |
| 2 | HTTP 200 | EPERM (`errno 1`) | 같은 Pod·시도 구간에서 확인 | HTTP 200 |
| 3 | HTTP 200 | EPERM (`errno 1`) | 같은 Pod·시도 구간에서 확인 | HTTP 200 |

세 회차 모두 응답 형식·대상 모델·생성 결과를 확인했고, 엔진 재시작은 0회였다. 시험 뒤 정책을 `monitor`로 되돌리고 Gateway 정책 묶음도 원복했다.

반복 검증에는 회차 실행기 커밋 `2ad459b2`와 관찰 대조 입력 보완 커밋 `18d555d4`를 사용했다. 결과는 `e7c05198`에 기록했다. 이 커밋들은 실행기와 결과 기록의 출처이며, 엔진 이미지 판본은 별도다. 반출한 반복 검증 요약 `summary-safe.json`의 SHA-256은 `30d4c0938c3a1bef16e0e5ff8e3d69b2d5e2e8ada77cda4470fd37514e926d72`이며, 이 표는 해당 요약에서 발췌했다.

## 검증 범위

지정 셸 경로에 대한 정책은 선택한 엔진 Pod 전체에 적용된다. 검증한 전환 절차는 `monitor`에서 기동한 뒤 Ready 상태에서 `enforce`를 적용하는 방식이다. `enforce` 상태의 빈 캐시 기동, 다른 경로로 복사된 실행 파일, 셸을 호출하지 않는 Python 내부 동작, 비승인 코드의 로딩 자체는 이 검증 범위 밖이다.
