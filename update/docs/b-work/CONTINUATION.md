# BYUL UPDATE B — 계속 진행 기준

사용자가 2026-10-30 명시한 지속 작업 지침이다. B 세션과 B subagent에 적용한다.
착수·작업 묶음 전환·최종 답변 전에 이 파일과 최신 session-checkpoint.json을 읽는다.

## 종료를 판단하는 기준

- 묶음·커밋·PR 완료, CI 결제 차단, A 답변 대기, AWS/GPU 부재를 B 작업 전체의 종료 사유로 삼지 않는다.
- 실측 대기와 개발 대기를 구분한다. 환경이 없어도 승인된 B 전용 입력·명령·실제 수집 코드·판정·EVD→RES→RPT·복구/정리·직접 회귀를 구현할 수 있으면 계속한다.
- 현재 묶음이 끝나면 같은 코드·관측을 공유하는 다음 미완료 분기를 즉시 착수한다. 기존 코드·시험·증거를 재사용한다.
- 중간 현황·사용자 질문에 대한 답은 commentary로 보낸 뒤 작업을 계속한다. 현황 보고 자체를 최종 답변으로 바꾸어 작업을 끝내지 않는다.
- 최종 답변 전 남은 B38 분기에서 구현·연결·회귀·검토·실행 준비 중 독립적으로 가능한 일이 있는지 확인한다. 남아 있으면 배정하거나 직접 작업한다.
- 허용된 독립 작업이 실제로 모두 소진됐을 때만 구체적 원인·근거·남은 입력과 다음 실행 명령을 밝히고 대기를 보고한다. 일부 후보 확인만으로 나머지 전체를 개발 불가로 단정하지 않는다.

## 보류는 해당 조건에만 적용

- A의 공통 파일은 A가 단일 작성한다. 필요한 입출력·관측 경계를 구체화해 요청하고, B 전용 수집·소비·판정·실행 준비는 별도로 진행한다.
- 미확정 기업 정책·수락 기준·공용 계약·소유권은 임의로 정하지 않는다. 기존 계약으로 만들 수 있는 부분부터 구현하고 미확정 연결만 표시한다.
- 없는 관측을 채우거나 전체 UNKNOWN만 내는 새 wrapper, 중복 helper·팩을 만들어 진행 수를 늘리지 않는다. 각 구현은 CheckDef의 실제 질문에 답할 수 있어야 한다.
- 실제 GPU/배포 결과는 해당 환경에서 검증한다. CPU·EXAMPLE·대역·정적 준비를 실측으로 집계하지 않는다.
- 전체 체크리스트 완료, 선정 분기 로컬 검증, 실행 준비, 실제 환경 미실측을 구분한다.

## 운영

- 사용자 승인 범위 안에서 구현 agent 최대2개(Sol/medium)와 고정 변경 집중 검토1개(Sol/high)를 재사용한다. 작업 파일·worktree·브랜치를 분리한다.
- agent 사용 한도·실패로 멈추면 현재 변경을 보존해 다른 agent 또는 주 세션이 이어받는다. 기술적 선행 조건과 agent 가용성을 구분한다.
- source를 고정한 뒤 직접 영향 회귀·집중 검토를 한다. 통과한 시험은 새 변경·실패·구체적 결함이 있을 때만 다시 실행한다.
- PR은 재사용 가능한 묶음으로 기존 PR에 모은다. PR 또는 CI 대기 중 다음 독립 개발을 한다.
- 사용자·A 변경, 과거 증거·Ref·sources를 보존한다. 강제 Git 작업·임의 merge/rebase·공유 환경 중단·승인 밖 AWS Start/자원·비용 확대는 하지 않는다.
- 최종 답변 전 확인 결과와 다음 배정을 checkpoint의 continuation_gate에 남긴다. 백그라운드 작업·스케줄이 실제로 없으면 실행 중이라고 말하지 않는다.
