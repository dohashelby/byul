# B 담당 시험의 CPU 실행 원칙

2026-10-28 사용자 지시. 기존 인계 프롬프트의 CPU 시험·환경 준비 관련 제한을
다음 원칙으로 대체한다. 원본 인계 자료와 과거 실행 기록은 수정하지 않는다.
이 원칙은 REQ-10뿐 아니라 B 담당 시험 전체에 적용한다.

1. CPU에서 완료 가능한 분기는 실제 대상 코드 검증까지 진행한다. 대역 회귀는
   BYUL 실행·수집·판정 계약의 검증이며, 실제 라이브러리·파서·요청 클래스·프로세스를
   CPU로 검증할 수 있으면 그 단계도 수행한다. 실행 도구 작성만으로 완료하지 않는다.
2. 본인 작업 폴더의 격리 가상환경 준비, 고정 소스 취득과 시험용 의존성 설치는
   작업 범위에 포함한다. 통상적인 준비를 매번 다시 승인받지 않는다. 시스템 환경과
   제품 의존성/lock은 변경하지 않는다. 시험 환경의 실제 의존성과 출처를 별도 보존한다.
3. 운영 대상이 미정이어도 근거 있는 참조 판본을 고정해 실제 코드 CPU 검증을
   계속한다. 결과는 해당 참조 판본·경로에만 귀속하며 설치판/GPU/배포 결과와 구분한다.
4. A 인계 대기는 필요한 공통 등록·CLI·팩·센서 연결에만 적용한다. 독립 CPU 검증은
   계속하고, A의 확정 소스를 받은 뒤 제품 연결과 변경 영향 검증을 마무리한다.
5. GPU/실제 환경 분기는 가능한 코드·CPU 회귀와 입력·명령·계측·증거 저장·판정·
   중단/복구 준비를 갖춘다. 관측 코드가 빠져 있으면 실제 실행만 남았다고 보고하지 않는다.
6. 차단 기록에는 실제 시도 명령, 실패 원인, 부족한 자원·권한·정책과 재개 조건을
   적는다. 환경 미정만으로 분기 전체를 대기시키지 않고 독립 작업은 계속한다.
7. AWS/과금 자원, Docker daemon/컨테이너 운용, 대규모 모델 다운로드, 공유 환경
   변경, 새 제품 의존성·공용 계약·기업 정책 변경은 별도 실행 범위를 확인한다.
   이를 일반적인 격리 CPU 검증 전체의 대기 사유로 확대하지 않는다.

완료 보고는 대역 회귀 / 실제 코드 CPU 검증 / 제품 연결 / 실제 환경 검증을 구분한다.
가능한 CPU 검증이 남아 있으면 해당 묶음은 계속 진행한다.
