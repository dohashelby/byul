# 2차 발표까지의 진행 계획

**2차 발표는 11월 21일이며, 최종 PPT는 11월 18일까지 완성한다.**

김민기·신가영은 **11/4~5 발표 흐름을 작성**한다. 신가영은 **11/7부터 PPT 제작에 집중**하고, 이도하·허영조는 발표 자료를 제공하면서 최종 발표용 개발을 이어간다.

## 1. 역할

| 담당 | 맡을 일 |
| --- | --- |
| **김민기** | R 검토 통합, 위협·프레임워크·체크리스트·정책·판정 기준 정리. 10월 말부터 런타임 개발 합류. 기업 컨택, 분석 그림, 발표 흐름·내용 검수 |
| **이도하·허영조** | 검증 도구·시험 환경·엔진 확장·증거·비교·보고서 공동 개발. 매주 작업별 주담당을 정하고 서로 실행해 확인 |
| **신가영** | 런타임 설계·초기 구현 후 김민기와 기능 분담. 개발 내용과 실행 방법을 인계하고 발표 흐름·PPT 제작 담당 |

초반부터 설계와 구현을 병행한다. 김민기는 준비된 평가항목부터 전달하고, 개발팀은 필요한 설정값·증거·판정 관련 질문을 돌려준다.

## 2. 주간 계획

### 1주차 · 10/19~25 — 분석 통합·개발 설계·첫 실행

| 담당 | 작업 |
| --- | --- |
| **김민기** | R 수정안 검수·통합. 환경별 조건과 위협·평가 질문 정리. 첫 평가항목의 정책·입력·증거·판정 기준 전달. 기업 검토 일정 요청 |
| **이도하** | 기존 검증 도구의 재사용·수정·신규 개발 범위 확인. 환경 입력→항목 선택→시험 호출→결과 조회 구조 설계. 첫 시험의 저장·조회 연결 |
| **허영조** | 공통 vLLM 환경의 일반·스트리밍 요청 확인. 엔진별 시험 버전 쌍·모델·GPU 계획 수립. SGLang 기동과 TensorRT-LLM 장비·설치 가능성 확인 |
| **신가영** | 기존 런타임 구현 확인. Gateway·송신 통제·관측 구성과 연동 방식 설계. 테스트 정책 하나를 적용해 허용·거부·적용 상태 확인 |

**이번 주에 함께 정할 것**

- 엔진별 필수 구현·시험 목록과 완료 기준
- 보안·정상 기능·품질·성능 시험의 입력 데이터와 기준값
- 실행 ID, 엔진·모델·설정, 정책·시험 판본, 워크로드·시각을 연결하는 증거 형식
- 자동 시험, 수동 확인, 미확인·해당 없음의 처리 방식
- 개발 구조·사용 흐름 그림 초안

**완료 확인:** 평가항목 하나를 실제로 실행하고 결과·증거를 조회한다. 런타임 정책 하나의 적용과 허용·거부 결과도 확인한다.

### 2주차 · 10/26~11/1 — vLLM 연결·SGLang 적용 시작

| 담당 | 작업 |
| --- | --- |
| **김민기** | 프레임워크 1차본과 기업 검토 자료 준비. 위협·통제 매트릭스에 관련 ATT&CK·ATLAS 참조와 통제·관측 위치 연결. 평가항목 순차 전달. 런타임 개발 합류 |
| **이도하** | 환경별 항목 선정·선정 이유·미확인 처리, 시험 호출·증거·판정·보고서 연결. 수동 확인과 승인·보류·예외 기록 구현. SGLang에 필요한 변경 시작 |
| **허영조** | vLLM 선정 시험과 정상 기능·품질·성능 측정 구현. SGLang 공통 시험 적용 시작. TensorRT-LLM 환경을 점검하고 첫 시험 시도 |
| **신가영** | vLLM의 접근·송신 통제와 이벤트·상태 수집 연결. SGLang 설정 차이 확인. **10/29까지 실행 방법·남은 작업을 김민기와 공유하고 기능별 담당 확정** |

**업무 분산**

- 이도하·허영조는 설계 때 만든 구현 관련 그림을 **10/29까지 한 번 갱신**한다. 11월 초에 새로 그리기 시작하지 않는다.
- TensorRT-LLM은 환경 준비와 첫 시험 착수 범위로 진행한다. 전체 확장 개발은 이후 최종 발표용 작업으로 이어간다.
- 신가영은 남은 런타임 기능을 혼자 모두 끝내려 하지 않고, 김민기와 정한 담당에 따라 개발한다.

**완료 확인:** vLLM의 대표 평가 흐름을 시험·보고서·승인 기록·정책 적용까지 연결한다. SGLang은 적용을 시작한다.

### 3주차 · 11/2~8 — 두 엔진 연결 완료·개발 인계·PPT 착수

| 담당 | 작업 |
| --- | --- |
| **김민기** | 런타임 공동 개발·시험, 기업 의견 반영. **11/2~3 신가영 담당 기능을 직접 실행해 인계 확인. 11/4~5 발표 흐름 작성.** 이후 런타임 보완 담당 |
| **이도하** | SGLang 입력→항목 선정→시험→증거·판정→보고서 연결. 운영 정책 적용 상태·이벤트 조회 연동. 발표용 화면·그림의 구조 확정 |
| **허영조** | 두 엔진의 필수 시험 수행. 허용·차단·탐지·관측 장애·정상 요청 유지·기본 복원 확인. TensorRT-LLM 첫 실제 시험 착수 결과 확보 |
| **신가영** | 11/2~3 담당 기능의 실행·오류 처리와 인계 보완. **11/4~5 발표 흐름 작성. 11/7부터 PPT 제작 전담** |

**완료 확인**

- **11/8까지** 두 엔진에서 10/25에 정한 필수 기능의 연결을 완료한다.
- 시험한 엔진·모델·설정과 실제 정책 적용 대상이 일치하는지 확인한다.
- 신가영의 개발 인계는 문서 전달에 더해 **김민기가 직접 실행한 상태**로 완료한다.
- 신가영에게 PPT 기간의 개발·시험 업무를 다시 배정하지 않는다.

| 담당 | 작업 |
| --- | --- |

- 기업 의견의 반영 내용과 미반영 사유
- 시험한 범위와 미실행·시험 불가·비적용 항목 및 이유
- 다른 팀원이 안내만 보고 실행하는 교차 재현
- 발표용 화면·그림·예비 시연 자료 전달

**11/15에는 김민기와 각 담당자가 PPT의 주장·수치·지원 범위를 확인한다.**

### 5주차 · 11/16~21 — 최종 PPT·발표 준비·최종 개발 지속

| 담당 | 작업 |
| --- | --- |
| **김민기** | 발표 대본·질의응답 준비, PPT 내용 검수. 런타임의 발표 필수 결함 대응과 개발 관련 결정 처리 |
| **이도하** | 최종 발표용 도구 개발 지속. 발표용 보고서·증거 조회와 관련 결함 대응 |

이도하·허영조는 **11/13부터 발표 대응 담당을 번갈아 정한다.** 담당자가 자료 요청과 시연 점검을 먼저 처리하고, 다른 사람은 최종 개발을 이어간다. 결함 수정은 해당 기능을 아는 사람이 맡는다.

11/19~20에는 리허설·시연에 필요한 시간을 확보한다. 금요일인 11/20의 참여 시간은 미리 합의한다.

## 3. 발표용 기준본과 최종 개발

| 구분 | 관리 방식 |
| --- | --- |
| **2차 발표용 기준본** | 코드, 이미지·의존성, 모델 식별값, 설정·정책, 시험 절차, 결과·증거, 시연 방법을 함께 보존한다. 최종 개발 때문에 시연 환경을 덮어쓰지 않는다. |
| **최종 발표용 개발** | TensorRT-LLM 확장, 세 엔진 공통 처리, 추가 평가항목·시험, 사용성·운영 개선을 계속 진행한다. |

최종 개발의 우선순위와 완료 기준은 **11/5까지** 정한다.

11/12 이후 발견한 문제가 발표 주장·수치를 바꾸면 김민기와 확인해 발표 기준본을 수정하고 재시험한다. 일반 개선은 최종 개발에 반영한다.

## 4. 인포그래픽

기존 그림을 수정·활용하고, **현재 결과물·시험 현황**과 **기업 활용·협력 제안** 두 장만 새로 만든다. 기업 컨택용 PDF와 발표 자료에는 목적에 맞는 그림을 선택해 사용한다.

### 그림별 작업과 담당

| 종류 | 작업 방식 | 담을 내용 | 초안 담당 |
| --- | --- | --- | --- |
| **운영환경·지원 범위와 정상 흐름** | 기존 그림 수정 | 기업의 요청·응답, 모델 반입·로딩, 운영 변경 흐름에서 프로젝트가 다루는 범위를 표시한다. 엔진·모델·배포·활성 기능별 **분석·구현·시험·계획 상태**는 하단 표로 구분한다. 상세 DFD는 별도 검토 자료로 유지한다. | **김민기** |
| **프레임워크와 솔루션 전체 구성** | 기존 전체 그림·프레임워크 구조도 수정·활용 | 전체 그림은 **프레임워크·업데이트 검증·런타임 통제의 역할과 결과물**을 보여준다. 프레임워크 구조도는 다섯 보안 영역·세 적용 관점과 체크리스트·가이드·시험·증거·판정 기준의 관계를 설명한다. 두 그림은 설명 목적에 따라 선택한다. | **김민기** |
| **위협·통제 매트릭스** | 예정 작업 유지 | 단순화한 정상 흐름에 지점 번호를 붙이고, 같은 번호를 매트릭스에 연결한다. **위협 성립 조건 → 보호 요구 → 통제·관측 위치 → 시험·증거**를 정리한다. 대표 공격 경로 1~2개는 상세 예시로 포함한다. | **김민기** |
| **체크리스트·평가 흐름** | 예정 작업 유지 | **환경·변경 정보 → 항목 선정 → 자동 시험·수동 확인 → 증거 → 판정·검토**를 보여준다. 선정·제외 이유, 증거 부족·미실행·해당 없음의 처리와 보완 후 재시험도 표시한다. | **이도하** — 김민기 기준·허영조 시험 절차와 대조 |
| **솔루션 구조·운영 흐름** | 기존 그림 수정 | 업데이트 전 비교 시험·보고서·담당자 승인과 운영 중 Gateway·직통 제한·송신 통제·구성 관측의 연결을 보여준다. **직접 개발하는 기능과 기존 도구 연동**, 정책 설정과 실제 적용 결과, 차단과 관측을 구분한다. 업데이트 시험 통과가 자동 배포로 이어지는 것처럼 표현하지 않는다. | **허영조** — 이도하·신가영과 연결 확인 |
| **사용자 입력·결과·운영 설명** | 예정 작업 유지 | 실제 화면·보고서·알림을 활용해 **사용자가 입력할 정보, 확인·승인할 지점, 받는 결과, 이후 조치**를 설명한다. 환경 등록·시험 실행·수동 검토·보고서 확인·운영 알림의 대표 사용 과정을 보여준다. | **이도하** — 허영조 시험 결과·런타임 담당자 자료 반영 |
| **현재 결과물·시험 현황** | **신규 1장** | 위쪽에는 실제 분석 발췌·대표 평가항목·도구 화면·개별 시험 결과를 배치한다. 아래에는 보호 영역 또는 확정한 유형별 **연결 사례·평가 질문·시험 명세 상태·실행 및 증거 상태**를 표시한다. 미실행·미확인도 명시하고, PDF의 기존 ‘현재까지의 분석·설계 결과’ 표를 대체한다. | **김민기 통합** — 이도하·허영조·런타임 담당자가 실제 자료와 상태 제공 |

### 공통 확인 사항

- 다섯 보안 영역과 주요 용어를 문서·그림 전체에서 통일한다.
- 실제 실행, 합성 자료를 이용한 확인, 설계, 향후 계획을 구분한다. 버전·수치·사례 수는 원본 근거를 확인한다.
- 기업용 자료에서는 내부 R 번호만 적지 않고 분석 대상과 의미를 풀어 쓴다.
- 요청·응답 경로, 모델 공급물과 실행 중 모델, 통제·관측 위치가 실제 구조와 맞는지 확인한다.
- 맞춤법 검사 물결선, 발표 화면의 머리글·쪽번호, ‘BoB 기업’ 등 내부 표현을 제거한다.
- 기존 아이콘은 유지한다. 왼쪽 세로 색 띠와 같은 계열의 연한 배경을 결합한 카드 디자인은 사용하지 않는다.

**신가영은 PPT의 배치와 표현을 통일한다. 내용 조사·초안 작성·실제 결과 확인은 각 담당자가 맡으며, PPT 전담 기간에 개발·시험 업무를 추가하지 않는다.**

## 6. 2차 발표 완료 기준

- 환경별 적용 조건과 위협·통제 매트릭스, 정책·체크리스트·가이드·시험·판정·승인 기준이 연결돼 있다.
- 관련 공격 활동에 ATT&CK·ATLAS를 참조하고, 통제·관측 위치와 대표 공격 경로를 설명한다.
- vLLM·SGLang에서 선정한 필수 항목의 입력→시험→증거·판정→보고서가 실제로 동작한다.
- 수동 확인과 검토·승인·보류·예외 기록을 도구에서 관리한다.
- 두 엔진에 Gateway·직통 제한·송신 통제를 적용하고 허용·차단·선정 행위 탐지와 정상 요청 유지를 확인한다.
- 정책 적용 실패·구성 변경·센서 중단·중앙 연결 단절을 확인하고, 알림·재검증 요청·기본 복원을 검증한다.
- 시험 대상·정책 적용 대상·관측 증거가 같은 환경과 실행을 가리킨다.
- TensorRT-LLM 환경 준비와 첫 실제 시험 착수 결과를 남긴다.
- 기업 1차 검토 결과와 재현·운영 자료를 제시한다.

**10/25와 11/1에는 실제 실행 결과로 남은 작업을 점검한다.** 두 엔진의 필수 완료 범위는 10/25에 명확히 정하고, 전체 위협 목록의 미확인은 별도로 유지한다. 지연이 생겨도 신가영의 PPT 전담 기간에 개발을 다시 얹지 않는다.
