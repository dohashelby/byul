# M-B1 공통 입력 소비 연결 검증

2026-11-13. `/4` 소비 구현은 #262, REQ-12 점검 선언·반환은 #257에 있다. 이 문서는 두 작업을 통합한 소스에서 기존 소비·판정·증거 저장 경로를 확인한 후속이다. GPU 실증 완료 기록은 아니다.

| 경계 | 확인한 동작 | 남은 범위 |
|---|---|---|
| `/1`~`/4` 읽기 | 기존 계약별 검증을 유지하고 `/4` 반복 요약은 펼치지 않는다. 소비 개수는 원 행 수를 반영한다 | 실제 새 생산자 자격은 GPU 확인 뒤 등록 |
| REQ-12 선언 | `request-attempt`가 REQ-12를 선언하고 기존 request_termination dispatcher가 선택한 실행기에 공통 입력을 전달한다 | 늦은 출력 수신자·취소 정책·자동 retry의 실제 근거 |
| 신원·자격 | 외부 ENV/target/prepared/session·현재 소유자를 대조한다. 미등록 소스와 `/4` 미등록 wire는 완료를 만들지 않는다 | 실제 ENV/target·worker 신원·정상/장애 관측 |
| 판정 | 공통 입력만으로 질문 전체를 완료하지 않는다. 미완료는 UNKNOWN을 유지하고 기존 독립 FAIL은 보존한다 | 두 판본 J01/J02 실측·정식 결과 |
| 저장·복원 | 원 record bytes 의미, EVD·RES·RPT 정확 Ref, 저장된 @34 팩을 이용한 재판정 결과를 보존한다 | 현재 시험 출처는 EXAMPLE이며 공식 결과가 아님 |

직접 영향 시험 84개가 통과했다(20.08초). 소비·판정·저장/복원 및 기존 REQ-12 제품 경로를 포함한다. 추가한 `tests/test_mb1_req12_current_pack.py`의 8개 사례는 @34의 REQ-12를 실제 선택·실행·판정·보고·반출·복원한다. `/1`·`/4`, 미등록·사례 내부 모의 등록, 독립 FAIL 유무를 나눈다. 모의 등록은 pytest 사례에만 적용하며 실제 GPU 등록을 추가하지 않는다.

8개 사례가 통과했다(6.17초). 근거 부족 시 UNKNOWN, 별도로 확인된 위반이 있으면 FAIL, 공통 입력의 전체 질문 완료·생산자 인증은 false, 출처는 EXAMPLE임을 확인한다. 정상/장애 전송은 기존 모의 엔진 자료이며 엔진/GPU·클라우드를 실행하지 않는다. main b1d209fc 통합 뒤 새 회귀·경로24개를 재확인했고 통과했다(12.82초). 현황·소스 고정 관문·diff 검사도 통과했다. 전체 로컬 pytest는 실행하지 않았다. 후속 PR CI와 병합은 별도로 남는다.

다음은 M-B4의 scheduler·전환·출력·profiler·공급 관측 의미와 두 판본 고정값이다. 기준 V0 D1~D3, 설치 이미지 bytes·CPython 자격, 실제 GPU 등록·입력 사전 점검을 이 검증으로 완료 처리하지 않는다.
