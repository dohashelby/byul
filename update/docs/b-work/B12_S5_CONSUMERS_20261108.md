# B1/B2 S5 소비 연결 — 37c284d9 기준

변경은 B 소비자와 CPU fixture 시험에 한정한다. A 공통 봉투·등록 SHA·producer/callback·core/models/store/judges/packs는 바꾸지 않는다. GPU/AWS/Docker/모델 기동·다운로드는 하지 않는다. 원 자료/Ref와 25/18 실증 분류도 변경하지 않는다.

## B1 입력 경로

기존 input_validation/sampling_validation factory의 실제 collect → _finish에서 선택적 `runner_input`을 소비한다. SUP-03 template factory의 _finish는 `supply_reads_input`을 소비한다. Kubernetes 소비자도 같은 경계를 사용한다.

각 설정은 `path`, 파일 bytes `sha256`, 독립적으로 고정한 `scope`(environment_ref, target_sha256, prepared_sha256, session)를 요구한다. runner에는 `requests`(기존 사례 이름 → 실제 관측된 request SHA)가 추가로 필요하다. 기대 scope를 record에서 복사해 채우지 않는다. 파일 크기·정규 파일·FD 전후 신원·SHA를 확인한 뒤 원 A `gpu_common_inputs.validate`를 호출한다. 외부 파일 입력의 `data_origin`은 EXAMPLE 기본이며 DECLARED만 명시할 수 있다. MEASURED 입력은 허용하지 않는다.

REQ-08은 counts만으로 token 값의 동일성을 만들지 않는다. 기존 trials 아래 runner metadata와 별도 artifact를 추가하며 원 state/독립 위반은 유지한다. REQ-09는 명시한 token_id/length 사례의 실제 runner 값이 기존 vocab/길이 한도를 넘은 경우에만 기존 confirmed_input_violations에 추가한다. 거부 요청이 도달했다는 사실만으로 변환 후 값의 위반을 추정하지 않는다.

S6의 고정 edaa6570 검토에서 REQ-09 세대 불일치 gap 뒤에도 새 확정 위반이 추가되는 결함을 확인했다. 요청별 pod/container/restart 결합과 선택된 기록 내 PID/start_ticks 재사용을 별도로 확인하여 미확정 사례의 신규 확정 위반을 막는다. 전체 complete를 요구해 기존 독립 위반을 지우는 방식은 사용하지 않는다. 원 검토 fixture 및 실패 패킷 v1은 보존하며 새 커밋/패킷으로 구분한다.

REQ-10은 기존 모든 functional/challenge 사례의 request 결합·API 결과·runner/sampler 단계·값/순서와 등록/완전성을 확인한 범위에서만 기존 runner_consumption_verified를 채운다. 원 /1에 없는 min_tokens, structured-output, V2 전체 count 값은 소비 검증으로 채우지 않는다. min_tokens가 선정되면 FIELD_UNSUPPORTED gap과 UNKNOWN/PASS 차단을 유지한다. 기존 judge에 없는 새 security FAIL 규칙은 추가하지 않는다. value mismatch는 artifact 후보/불완전으로 남기며 기존 기능 FAIL은 지우지 않는다.

supply-reads의 A checks는 SUP-03뿐이다. SUP-05나 SUP 전반으로 확대하지 않는다. open/hash·inotify 귀속은 실제 decoder/tensor·권한 있는 승인 기준이 아니다. 이 연결로 template_consumer_verified/supply_scope_complete를 올리지 않는다.

새 top-level 관측에 의존하지 않는다. core._normalize를 통과하는 기존 관측과 내용주소 artifact `b_common_consumption.json`에 원 record/독립 scope/투영·gap을 보존한다. 요청한 새 입력이 누락/미등록/상충하면 ABORTED로 PASS를 차단하되 원 독립 FAIL은 유지한다. artifact 쓰기 오류도 원 위반을 지우지 않는다. 선택적 설정이 없으면 기존 동작을 유지한다.

## B2 공급물 경로

SUP-06의 normal/challenge role 설정에 선택적 worker_shard_input(동일 파일 입력 계약)을 받는다. env/target은 현재 역할, prepared는 기존 역할 정책과 대조한다. A worker_shard_producer.shard_rows가 만든 5키 중 원 3키만 기존 boot row/판정에 투영하고 load_completed/load_failed는 별도 session 관측으로 보존한다. 원 validate_record의 3키 계약은 변경하지 않는다. worker-shard는 현재 미등록이므로 supported/complete=false와 gap을 유지한다. 후보를 새 확정 위반으로 승격하지 않으며 별도 legacy boot/native 기록의 FAIL은 보존한다.

SUP-09/11은 guard-model-entry/1, SUP-10은 guard-plugin-runner/1 행을 분리해 원 A evaluate를 호출한다. legacy 투영과 새 투영의 위반·누락을 함께 유지한다. 새 행만으로 기존 dynamic 12/plugin 10 사례를 대체하지 않는다. 혼합/빈/알 수 없는 contract도 기존 위반을 지우지 않는다. 원 model_entry fixture의 -OO 정상 대조 실패는 고치거나 지원으로 이름 바꾸지 않고 UNKNOWN으로 유지한다. 실제 동적 코드나 plugin은 시험 중 실행하지 않는다.

## 검증과 잔여

신규 test_b12_runner_consumers.py/test_b12_supply_consumers.py는 원 producer 함수와 커밋된 model-entry/plugin/worker-shard fixture를 사용한다. 등록 SHA monkeypatch/등록 상승은 없다. 전송은 CPU fixture이며 실제 GPU/배포 결과가 아니다. 등록 factory의 실제 collect/_finish → core 정규화 → EVD·artifact 저장 → 원 judge를 확인하고, 기존 boot validate → evaluate → 원 judge도 확인한다.

남은 반환물은 실제 runtime request fingerprint/ENV/target/prepared/session 결합, worker-shard TP2 확인·등록, model-entry -OO 라이브러리 지원, SUP-03 실제 aux 소비/승인 결합, REQ-09 MM/offset 및 REQ-10 min_tokens/V2/structured backend의 공식 소비 계약이다. 이 미완 분기는 현재 연결 가능한 CPU 소비 경로의 선행 gate가 아니다.

B4 prepare-only generator는 역할 조정으로 root 단독 작성이며 S5는 관련 파일을 만들지 않았다. S2가 tp2-run-plan.md의 B절을 단독 작성한다.
