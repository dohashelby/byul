# UPDATE 실행 구조 및 중복 코드 감사

기준은 2026-11-24의 codex/update-structure-refactor 작업 트리입니다. Git 기준 커밋은 3f728ee320685f200f302490ba4de6145454334c이며, 같은 관측 기록의 파일 읽기를 공유하는 작업 트리 변경까지 포함했습니다. 범위는 UPDATE의 실행, 준비, 관측, 수집, 증거 변환과 이를 호출하는 PACK·시험·도구입니다.

첫 변경 묶음은 소유권이 확인된 고정 기록 리더 5개를 1개로 통합하고, 공용으로 옮길 수 있는 호스트의 검증·증거 조립 코드와 중복 조회를 정리하는 범위입니다. 현재 자격 검증이 해시로 고정한 소스는 각 증거가 읽는 이전 소스를 보존하고, 새 구현의 실제 의존성까지 검토하는 전환 범위에 들어갑니다.

## 적용 현황

본문과 부록의 최초 발견 위치와 목표는 감사 당시 기준입니다. 아래 결과는 실제 변경 기준입니다.

### 추가 적용

| 적용 항목 | 확인된 변화 |
|---|---|
| 모델 기록 투영 | 가중치 순회 구현 **4 → 1**, 파일 매핑 구현 **2 → 1**. 같은 기록 안에서 후보별로 다시 훑던 가중치 행은 한 번 인덱싱합니다. 기존 이벤트 위치와 상한을 유지했습니다. |
| 제출된 runner·supply 기록 | 해당 PLAN 레시피가 읽은 바이트를 같은 점검에서 재사용해 안정적인 파일의 본문 읽기 **2회 → 1회**. 파일을 여는 권한, 크기, 해시, ENV와 대상은 검사합니다. 레시피 이후 파일이 바뀌거나 새로 나타난 경우를 검증하는 회귀를 추가했습니다. |
| runner 기록 투영 | 필요한 사례가 N개일 때 전체 이벤트 순회 **2N+1회 → 1회**. 입력 계약 검증과 사례별 선택된 행의 확인은 별도입니다. |
| 고정 입력과 자산 | 오프라인 CPU·runner 파일의 제한 읽기 본문 **2 → 1**, process·mount·file access·GPU의 호스트 자산 검증 **4 → 1**. file access, GPU의 생성 소스와 멀티모달 CPU 스크립트 두 개는 이전 바이트와 일치합니다. |
| 관측기 자산 준비 | 콜백 설정과 매니페스트의 옵션 조립 **2 → 1**, 설치 소스 SHA 계산 본문 **2 → 1**, lifecycle 확장 바이트 조립 **4 → 1**. 설치 자산과 다섯 프로필의 조립 바이트를 대조했습니다. |
| 관측 증거 마무리 | 출처 상한과 실행 상태, 정리 오류를 적용하는 본문 **11 → 1**. 점검별 누락 조건과 자체 중단 사유는 기존 경로에서 결정합니다. |
| 생산자 소스 지문 | 등록되지 않은 생산자 네 곳의 소스 지문 루프 **4 → 1**. 공용 파일까지 지문에 포함하며 기존 GPU 지원 목록과 보존 기록을 유지합니다. |

PLT-01·04 실행기와 Docker의 공통화 후보는 현재 worker-security 자격 검증이 읽는 파일에 있습니다. HTTP 준비, REQ-10 CPU 컴포넌트와 설치된 관측기·기록기는 각각 검토 소스 또는 설치 자산 지문을 사용합니다. 관련 항목을 적용하려면 실제 이미지와 새 소스 범위를 대조해 자격을 확인해야 합니다. source-CPU 프로파일러는 기존 경로에서도 실행기 하나만 만듭니다. 패키지 내부 모듈 삭제 후보는 기존 테스트가 호출하며, 저장소 밖 호출 여부는 확인되지 않았습니다.

공개 등록 키 54개와 capture 명령 8개를 대조했습니다. worker-security, native-input, 검토된 readiness·HTTP 및 경계 송신의 고정 소스 바이트는 동일합니다. 어댑터 경로의 ready·public_routes, 기록 투영과 설치·기록기 전환은 아래 소스 전환 범위에서 다룹니다. 집계의 실행기 호출과 파일 읽기 수는 구현과 계수 회귀 기준입니다. Linux 회귀 실행과 실환경 경과 시간 비교는 남아 있습니다.

## 이미 공유하는 구현과 서로 다른 관측 시점

- Docker·Kubernetes 세션 명령은 공용 capture_session 하나를 호출합니다. 네 CLI의 파일 저장·해시·실패 적용은 이번 작업 트리에서 이미 공유합니다. [Docker 진입](../src/guard/collectors/lifecycle.py#L533) · [Kubernetes 진입](../src/guard/collectors/kubernetes_lifecycle.py#L37) · [공용 저장](../src/guard/cli.py#L663)
- PLT-01·04의 프로세스 수집기는 이미 하나입니다. 같은 Pod에서도 점검 사이에 PID와 마운트가 바뀝니다. PLT-04가 기존 PID 목록을 사용하면 새 프로세스의 금지 마운트를 놓칠 수 있습니다. 두 점검이 명시적으로 같은 파일 기록을 제공한 경우에만 작업 트리의 공유 경로가 적용됩니다. 단일 측에서 본문 읽기 5→3, JSON 해석 2→1은 코드와 회귀 조건에서 집계했습니다. [프로세스 소비](../src/guard/executors/container_config.py#L126) · [마운트 확인](../src/guard/runtime/kubernetes_process_mounts.py#L59) · [호출 수 회귀](../tests/test_b12_common_input_consumption.py#L166)
- 별도 계약으로 제출된 같은 runner 관측 기록의 재사용도 가능한 후보입니다. 동일 파일·해시·ENV·세션·대상과 준비 기록을 각 호출에서 대조하고, 요청별 자극과 서로 다른 시점의 새 관측은 각 점검에서 확인합니다. [제출 기록 승인](../src/guard/executors/common_consumption.py#L31)
