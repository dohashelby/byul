LSM 정책의 핵심 형식은 다음과 같다. 저장소 생성기는 실제 enforce 전에 monitor로 로드한다.

```json
{"lsmhooks":[{"hook":"file_open","args":[{"index":0,"type":"file"}],"selectors":[{"matchArgs":[{"index":0,"operator":"Equal","values":["/run/byul-probe/secret.txt"]}],"matchActions":[{"action":"Post"},{"action":"Override","argError":-13}]}]}]}
```

## 구현에 반영할 판단과 한계

- 명시적 방식 이름은 `lsm_file_open`. 추천 순서는 `lsm_file_open` > `override_syscall` > `sigkill_fd_install`. 기존 intent·묶음의 방식은 자동 전환하지 않는다.
- [1.7.1 LsmHookSpec](https://github.com/cilium/tetragon/blob/v1.7.1/pkg/k8s/apis/cilium.io/v1alpha1/types.go#L401-L419)은 data를 지원하지 않는다. [ProcessLsm](https://github.com/cilium/tetragon/blob/v1.7.1/api/v1/tetragon/tetragon.proto#L612-L631)도 data·return 필드가 없다. 따라서 KERNEL_DATA를 넣거나 kernel_read_denied를 반환값에서 추정하지 않는다. 귀속된 이벤트와 직접 errno 증거가 필요하다.
- openat 문자열 Equal 값 끝의 `\u0000`은 기존 생성 코드가 명시적으로 추가한 종결자다. [1.7.1 writeMatchStrings](https://github.com/cilium/tetragon/blob/v1.7.1/pkg/selectors/kernel.go#L701-L707)와 [ArgStringSelectorValue](https://github.com/cilium/tetragon/blob/v1.7.1/pkg/selectors/selectors.go#L353-L359)를 확인하면 string Equal은 끝 NUL을 제거한 뒤 비교하므로 필수는 아니다. 실측에서 매치된 것과 일치한다. 기존 생성값 호환성을 위해 보존하며 제거 대조 실험은 미실행이다.
- syscall 방식의 상대 경로·symlink·TOCTOU·openat2·io_uring 우회 한계를 명시한다. LSM도 이미 열린 descriptor의 읽기를 차단하는 방식은 아니다.
- Sigkill 없는 두 방식에는 엔진 종료 안내·ENGINE_RESTART 확인이 불필요하다. 기존 Sigkill 포함 묶음은 실제 action을 기준으로 계속 확인한다.
- 활성 BPF LSM 또는 `tetra probe lsm:true`는 사전 조건을 충족하는 후보 판정이다. 실제 정책 로드·검증 증거·운영 안전 조건을 대체하지 않는다.

## 남은 확인

이번 저장소 변경으로 생성한 정책의 AWS 재실행, 새 LSM 방식의 native 귀속·trial·대시보드 운영 전환 전체 경로와 실제 엔진 본체 접근은 미실행이다. 수동 시험 증거를 자동 trial 성공 보고서로 재포장하지 않는다. 서버 준비 명령은 [GPU LAB README](../deploy/gpu-lab/README.md)의 BPF LSM 절차를 따른다. Claude가 코드·문서·시험 결과를 직접 검수해야 한다.
