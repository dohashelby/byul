## 1. 동작 요약

| 항목 | 내용 |
| --- | --- |
| 화면 | 로그인 화면만 있다. 회원가입·비밀번호 찾기는 없다 |
| 첫 계정 | 계정 파일이 없으면 `admin` / `admin`을 만든다. 서버 로그에 경고를 남긴다 |
| 기본 비밀번호 | 바꾸지 않아도 쓸 수 있다(개발 중). 상단에 "기본 비밀번호(admin) 사용 중" 경고를 띄운다 |
| 변경 강제 | `BYUL_REQUIRE_PASSWORD_CHANGE=1`이면 변경이 필요한 계정은 비밀번호 변경·로그아웃만 할 수 있다. **기본은 꺼짐** |
| 계정 저장 | 파일 하나(0600, JSON). 비밀번호는 scrypt 해시만 저장한다. DB는 없다 |
| 세션 | HttpOnly·SameSite=Strict 쿠키(HTTPS면 Secure). 2시간 미사용 또는 12시간이 지나면 끝난다. 서버를 다시 켜면 다시 로그인한다 |
| 요청 위조 방지 | 값을 바꾸는 요청에는 로그인 때 받은 `X-CSRF-Token` 헤더가 필요하다 |
| 연속 실패 | 같은 아이디나 같은 접속 주소에서 10분 안에 5번 틀리면 5분 동안 막는다. "아이디 없음"과 "비밀번호 틀림"을 구분해 알려 주지 않는다 |
| 보호 범위 | `/api/auth/login`·`/api/auth/me`를 뺀 모든 `/api/*`가 로그인을 요구한다. 화면 파일(HTML·JS)은 열리지만 자료는 로그인 뒤에만 보인다 |
| 에이전트 | 서버 에이전트는 지금처럼 `BYUL_OPERATION_TOKENS`의 Bearer 토큰으로 운영 API만 쓴다. 사람 로그인과 분리돼 있다 |
| 감사 기록 | 계정 파일 옆 `auth-audit.jsonl`(0600)에 로그인 성공·실패·잠금·로그아웃·비밀번호 변경·계정 변경을 남긴다. 비밀번호는 남기지 않는다 |

## 2. 역할과 운영 요청

| 역할 | 조회 | 운영 요청 | 운영 승인 | 계정 관리 |
| --- | --- | --- | --- | --- |
| `admin` | ✅ | ❌ (목록만) | ❌ | ✅ 명령어 |
| `approver` | ✅ | ❌ | ✅ | ❌ |
| `runtime_operator` | ✅ | ✅ | LAB 자기 승인 설정 때만 | ❌ |
| `viewer` | ✅ | ❌ | ❌ | ❌ |

- 운영 화면은 로그인한 계정의 역할을 그대로 쓴다. 토큰 입력칸은 로그인이 꺼진 배포에서만 보인다.
- 자기 승인 금지는 계정 아이디로 판단한다. 요청한 계정과 같은 아이디로는 승인할 수 없다.
- 관리자는 요청·승인을 하지 않는다. 계정 관리와 승인 권한을 한 계정에 몰지 않으려는 것이다.
- 버튼을 숨기는 것은 화면 편의일 뿐이다. 최종 판단은 서버가 한다.

## 3. 계정 관리 명령

계정 파일 위치는 `--accounts-file`로 주거나, `BYUL_ACCOUNTS_FILE` 또는 `PLATFORM_DATA_DIR`(→ `accounts/accounts.json`)에서 정한다. 임시 비밀번호는 **새 0600 파일에만** 쓰고 화면에는 출력하지 않는다. 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 실패한다.

```bash
cd platform/api
uv run python -m byul_platform.accounts_cli list
uv run python -m byul_platform.accounts_cli create --id op1 --role runtime_operator --password-file /root/op1.pw
uv run python -m byul_platform.accounts_cli set-role --id op1 --role approver
uv run python -m byul_platform.accounts_cli disable --id op1
uv run python -m byul_platform.accounts_cli enable --id op1
uv run python -m byul_platform.accounts_cli reset-password --id op1 --password-file /root/op1-new.pw
```

| 명령 | 효과 |
| --- | --- |
| `create` | 계정과 임시 비밀번호를 만든다. "변경 필요"로 표시한다 |
| `disable` / `enable` | 지우지 않고 막거나 다시 연다. 막으면 그 계정의 세션이 바로 끝난다 |
| `set-role` | 역할을 바꾼다. 그 계정의 세션이 끝난다 |
| `reset-password` | 임시 비밀번호를 다시 만든다. 세션이 끝난다 |
| `list` | 아이디·역할·상태만 보인다. 해시는 보이지 않는다 |

마지막 남은 관리자 계정은 막거나 역할을 바꿀 수 없다(`LAST_ADMIN`).

## 4. 비밀번호 규칙

10자 이상, 아이디·`admin`·`password`와 다르게, 서로 다른 문자 4개 이상.

## 5. 서버에서 확인할 것

1. 첫 실행 뒤 `admin`/`admin`으로 로그인되고 경고 띠가 보이는지 확인한다.
2. 계정 파일과 감사 기록이 0600인지 확인한다.
3. 다른 브라우저에서 로그인하지 않고 `/api/meta`를 열면 401인지 확인한다.
4. 에이전트가 토큰으로 운영 요청을 계속 받아 가는지 확인한다.
5. `runtime_operator` 계정으로 요청하고 `approver` 계정으로 승인되는지 확인한다.

## 6. 하지 않은 것

| 항목 | 이유 |
| --- | --- |
| 계정 관리 화면 | 명령어로 충분. 필요하면 추가 |
| SSO·2단계 인증 | 나중에 붙일 수 있게만 둔다 |
| 여러 서버(프로세스) 사이 세션 공유 | 세션은 프로세스 메모리에 있다. 플랫폼은 한 프로세스로 실행한다 |
| 외부 주소로 열기 | HTTPS 검토 전이라 지금처럼 127.0.0.1만 허용한다(원격은 SSH 터널) |
