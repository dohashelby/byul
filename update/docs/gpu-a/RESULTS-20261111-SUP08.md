## 대조와 제한

0.31.0에서 `--trust-remote-code`를 끄고 같은 모델을 기동하는 대조는 모델의 사용자 정의 코드를 허용해야 한다는 구성 오류로 시작 단계에서 중단됐다. 정상 기능 대조가 성립하지 않아 이를 SUP-08 PASS로 세지 않았다. [vLLM 공식 권고](https://github.com/vllm-project/vllm/security/advisories/GHSA-h3rc-6mm3-gc2m)의 영향 범위는 `>=0.7.3,<0.31.0`이고 bisect가 끝나지 않았다. 이번 0.7.0 PASS는 고정한 모델·설정·요청에서의 실측이며 다른 배포의 안전성 주장으로 확장하지 않는다.

초기 시도에서 2048 토큰 길이는 Phi3V 정상 이미지 요청(2521 prompt tokens)에 부족했고, 0.30.0의 인코딩된 캐시 경로를 읽지 못해 `UNKNOWN`이 나왔다. 제품 비교 준비 중 복사한 PNG data URI가 8자 짧았던 실행은 0.7.0 이미지 디코딩 HTTP 500으로 `NOT_COMPARABLE`이 됐다. 해당 실패는 최종 PASS/FAIL로 세지 않았고 새 실행에서 검증된 정책 이미지 206자를 양쪽 설정에 사용했다.

증거 묶음 `SUP08-evidence-20261111.zip`은 저장소 밖 사용자 전달물이다(SHA-256 `719ccd77b9daf34d711e5c9691545b12e17e2644968c4e3bdedc97b73fc6b84a`, 998,017 bytes, 내부 40파일 해시 확인). 저장소에는 [PoC 요약 JSON](../evidence/sup08-code-selection-20261111.json)을 둔다. 묶음에는 최종 제품·0.7.0·0.31.0 Store의 `guard evidence export` 보존본, RPT/요약, ENV/target/렌더, fixture manifest, trust 비활성 기동 실패 로그가 들어간다. export 전 세 Store 모두 `guard verify`에서 `OK`였다. 모델 가중치 8.3 GB와 로컬 캐시는 증거 묶음에 넣지 않았다. 재현 시 `tools/prepare_sup08_phi3v_fixture.py --source <고정 원본 snapshot> --output <새 폴더> --run-id <고유 ID>`로 자료를 만들고, 묶음의 `render.json`, `guard.toml`, `policy.yaml`과 대상 Pod 바인딩을 사용한다.
