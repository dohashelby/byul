# 신가영 런타임 개발 범위

정리일: 2026-10-19. 제공된 프로젝트 요약과 2차 발표 계획에서 추린 **요구사항·계획**이다.
이 문서는 원문에서 추린 참고 요구사항이다. 사용자가 직접 작성 중인 개발계획서와 구분하며, 확정된 구현 범위·기술 스택이나 구현·시험 완료를 뜻하지 않는다.
전체 맥락은 `projectsummary.md`, 일정과 역할은 `2차발표계획.md`, 확인된 진행 상태는 `STATUS.md`를 참고한다.

## 1. 목표와 범위

운영 정책을 실제 대상에 적용하고 승인한 구성과 현재 상태를 비교한다.
정책 위반·구성 변경·관측 장애를 증거와 함께 표시하고 알림·재검증 요청으로 연결한다.

| 위치 | 필요한 기능·확인 |
| --- | --- |
| Gateway | 일반·관리 API 허용/거부 정책, 적용 상태, 호출 결과 |
| 엔진 직접 접근 경로 | Gateway를 우회한 접근에 대한 제한과 실제 접근 결과 |
| 호스트·컨테이너 송신 경로 | 목적지 주소·포트·프로토콜별 통제, 인터넷·사내 통신, 허용/거부 기록 |
| 배포 설정·실행 프로세스 | 엔진 버전·이미지·실행 옵션·모델 식별정보와 승인 구성 비교 |
| 엔진 로그·서버·GPU 지표 | 지원되는 오류·상태·자원 관측, 수집 시각과 최신성 |
| 정책 적용부·수집부 | 적용 실패, 오래된 관측값, 수집 중단·관측 불가 상태 |
| 관리 화면·API | 정책·적용 대상 관리, 적용 상태, 이벤트·증거 조회, 알림·재검증 요청 |

기존 Gateway·네트워크 통제·지표 수집 기능을 활용한다.
새로 개발할 중심은 정책·대상 관리, 연동과 적용 확인, 구성 비교, 알림·기록 조회다.
프레임워크·정책·판정 기준은 김민기, 업데이트 검증 도구·시험·보고서는 이도하·허영조와 맞춘다.
정책값·이벤트 스키마·연동 API·사용 기술은 현재 확정됐다고 가정하지 않는다.

## 2. 연동과 증거

- 시험한 엔진·모델·설정과 실제 정책 적용 대상이 일치해야 한다.
- 실행 ID, 환경·엔진·모델·설정, 정책·시험 판본, 워크로드·시각을 연결한다. 가능한 경우 요청 ID도 남긴다.
- 사용자가 설정한 정책과 실제 적용 결과를 별도로 확인한다.
- 엔진 직접 호출과 Gateway 경유 호출을 구분해 엔진의 효과와 앞단 차단 효과를 구별한다.
- 운영 정책 적용 상태와 이벤트는 검증 도구의 조회 흐름과 연결한다.
- 업데이트 시험 통과 뒤 최종 적용은 담당자 검토·승인으로 결정한다.
- 중앙 관리부와 연결이 끊겨도 마지막 승인 정책이 유지돼야 한다.
- 재시작·배포·복구는 담당자의 운영 절차에 맡긴다. 기본 복원의 시험 대상·절차는 실제 구성에서 구체화한다.

## 3. 확인해야 할 동작

2차 발표에서는 vLLM·SGLang의 선정된 필수 범위에 대해 실제 실행 증거를 확보한다.
세부 필수 목록과 완료 기준은 10/25 확정 계획이며, 현재 확정·완료 여부는 확인되지 않았다.

| 상황 | 확인할 결과 |
| --- | --- |
| 허용·거부 정책 적용 | 적용 대상·정책과 실제 허용/차단 결과가 일치 |
| Gateway 경유·직통 접근 | 경로별 제한과 정상 요청 유지 |
| 선정 행위 탐지 | 탐지 대상·조건·이벤트·증거가 연결됨. 차단 결과와 별도 표시 |
| 송신 통제 | 허용·거부 목적지의 연결 결과와 관측 기록 일치 |
| 정책 적용 실패 | 성공으로 처리하지 않고 실패·사유 표시 |
| 승인 구성 변경 | 차이 확인 → 알림 → 재검증 요청 연결 |
| 수집 중단·오래된 관측 | 관측 불가·최신성 문제를 표시 |
| 중앙 연결 단절 | 마지막 승인 정책 유지 확인 |
| 기본 복원 | 담당자가 정한 절차로 복원하고 정책·관측 상태 재확인 |

집계 GPU·서버 지표만으로 특정 요청의 자원 회수 완료를 단정하지 않는다.
파일 해시만으로 실제 로딩·소비한 대상의 일치를 단정하지 않는다.
추가 계측이 필요한 내용과 현재 관측 가능한 범위를 기록한다.

## 4. 역할 전환과 주요 기한

모두 2026년의 계획 날짜이며, 날짜 경과는 완료의 증거가 아니다.

| 기한 | 신가영 및 런타임 관련 계획 |
| --- | --- |
| 10/19~25 | 기존 구현 확인, 연동 설계, 정책 하나의 적용·허용/거부·상태 확인 |
| 10/29 | 실행 방법·남은 작업을 김민기와 공유, 기능별 담당 확정 |
| 11/2~3 | 김민기가 담당 기능을 직접 실행해 인계 확인, 오류 처리 보완 |
| 11/4~5 | 김민기·신가영 발표 흐름 작성 |
| 11/7부터 | 신가영 PPT 제작 전담. 이후 개발·시험을 다시 배정하지 않는 계획 |
| 11/8 | 두 엔진의 선정 필수 기능 연결 완료 |
| 11/12 | 발표용 코드·환경·정책·시험·수치·증거·시연 기준본 보존 및 교차 재현 |
| 11/18·11/21 | 최종 PPT 완성·2차 발표 |

인계에는 실행 명령, 설정·정책, 의존 도구·권한, 증거 위치, 오류 처리, 남은 작업과 담당이 필요하다.
문서 전달에 더해 김민기가 직접 실행한 상태로 인계를 확인한다.
발표용 기준본을 보존하고 최종 발표용 개발이 이를 덮어쓰지 않도록 한다.

## 5. 상태 해석

제공된 요약에는 송신 통제·Gateway 연동 설계와 정책·이벤트·적용 상태 형식·예시가 있다고 적혀 있다.
실제 정책 적용·수집·구성 비교·알림·조회 구현과 환경 시험은 남은 작업으로 적혀 있다.
현재 저장소와 실행 환경은 이 초안 작성 과정에서 확인하지 않았다. STATUS에 검증 결과가 쌓이면 그 근거로 갱신한다.
