### 엔진 대상 결과의 의미

Sigkill(`fd_install`)은 **그 파일을 연 프로세스**를 종료한다. 이번에는 `kubectl exec`로 엔진 컨테이너 안에 띄운 별도 Python이 읽었으므로 그 프로세스만 종료됐고 서비스는 중단되지 않았다. 엔진 본체 프로세스가 직접 보호 파일을 열면 엔진이 종료되고 재시작까지 Gateway가 503을 내는 것이 설계상 예상이며, 이번 회차에서는 재현하지 않았다. AWS 커널에서는 Override(읽기 거부)가 불가하므로(4회차 결과) 차단 수단은 Sigkill뿐이다.

| 1 | 시험 도구가 서버 노드를 항상 거부 | kubeadm hostname-override로 호스트명 ≠ 노드 이름 | machine-id 비교로 수정(`93558a6`, 머지) |

| 3 | 에이전트 보고 전체 422 | `monitor_only` 정책이 보고에 포함돼 플랫폼 계약 위반 | 전환 대상만 보고(`6dcd376`) |
| 4 | crictl 없음 | kubeadm 설치에 미포함 | 서버에 cri-tools v1.36.0 설치(SHA-256 확인), README에 절차 추가 |
| 5 | 이벤트 귀속 안 됨 | Gateway에 `--tetragon-identities` 누락 | **임시 우회**: 서버 Gateway에 인자 추가. 수정: `gateway.yaml`·식별 수집 서비스 추가 |
| 6 | 감시가 계속 "복구 중" | 30초마다 귀속 이벤트가 필요한데 AWS에 sentinel 없음 | **임시 우회**: sentinel 설치. 수정: `deploy/gpu-lab`에 sentinel·정책 추가 |
| 7 | sentinel 이벤트 `native_binary_conflict` | Tetragon은 실행 경로(`python` 심볼릭 링크), 식별 자료는 실제 경로(`python3.12`) | **임시 우회**: sentinel이 `python3.12` 직접 실행. 수정: inode로 증명한 실행 경로 별칭 허용 |
| 8 | 상태 수집기가 sentinel 생존 기록을 못 읽음 | Gateway가 0600으로 저장 | **임시 우회**: 상태 수집기를 root로 실행. 수정: 0640 |
| 9 | 모니터 생성기가 Gateway 관측 기록을 거부 | 소유자가 root·자기 계정만 신뢰, 관측 기록은 Gateway uid 10000 | **임시 우회**: root가 runtime-agent 소유 추가 전용 사본 작성. 수정: `--trusted-owner-uid` |
| 10 | 모니터 기간 미충족 | 플랫폼 `BYUL_OPERATION_MONITOR_SECONDS` 기본 86400, 에이전트는 큰 값 사용 | LAB 플랫폼을 60으로 실행, 절차에 기록 |

그 밖에 서버 상태: Gateway 데이터 폴더를 그룹 10000·0750으로 바꿨고, `runtime-agent`를 그룹 `serving-observe`에 넣었다. 호스트 수집 서비스는 부팅 시 옛 코드(`d0bf905`)로 떠 있어 새 코드로 재시작했다. 수행 중 노트북에서 띄운 Tetragon 이벤트 수집기가 기존 호스트 수집기와 같은 폴더에 약 1분 중복 기록한 뒤 종료했다(이후 감시 판정은 정상).

## 종료 상태

- 시험용 Pod 삭제, `runtime-tg-secret-01`은 monitor 유지, 엔진 대상 시험 정책 삭제. sentinel과 Gateway 식별 인자는 유지(다음 배포 정의와 같음).
- 에이전트 서비스는 중지·비활성화(설치본·sudoers 유지). 역방향 터널 종료. 현재 묶음 `bundle-aws-lab-dev-vllm-run5-op-a`.
- 의도한 시험 읽기는 `intended-reads.log`에 시각·목적을 남겼다. AWS-11 오탐으로 세지 않는다.
