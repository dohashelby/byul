# 알림 보내기 (15개 목록 13번)

> Claude가 구현함(Codex 사용 한도로 이어받음). **Codex 교차 검수 전**이며 실서버 확인 전이다.

`tools/alert_notifier.py`는 Gateway 읽기 API만 조회한다. 차단·이상 탐지·수집 중단이 생기면 웹훅(Slack·Discord·일반 JSON)으로 짧은 한국어 요약을 보낸다. **기본은 꺼짐**이고, `--send`가 없으면 보낼 내용을 화면에 출력만 한다.

## 1. 무엇을 알리나

| 종류 | 근거(Gateway API) | 심각도 | 방식 |
| --- | --- | --- | --- |
| Gateway 요청 차단 | `/api/requests?result=DENIED` | 주의 | 새로 생긴 건수와 이유 코드 집계 |
| Tetragon 허용 목록 밖 실행 탐지/차단 | `/api/observations?source=tetragon` 중 `process_exec`, `exec_verdict`가 `outside_allowlist`·`suspect_binary`·`exec_from_cache`인 것 | 탐지 주의, 차단(`action_mode=enforce`) 심각 | 규칙 ID·판정 집계 |
| Tetragon 보호 파일 접근 탐지/차단 | 같은 API의 `file_access` | 위와 같음 | 규칙 ID 집계 |
| Cilium 네트워크 차단 | `/api/observations?source=hubble`의 `verdict=dropped` | 심각 | 이유 코드 집계 |
| 수집 중단·복구 | `/api/collectors`(stale·error), `/api/tetragon-status`, `/api/gpu-status`, `/api/summary`의 기록 저장소, `/api/status` | 이상 심각, 복구 정보 | 상태가 **바뀔 때만** 보낸다 |
| Gateway 조회 실패·복구 | 두 번 연속 실패 | 심각 | 한 번만 보내고, 복구 때 다시 보낸다 |

- `phase_unknown`·`phase_signal_unverified`처럼 판단할 수 없는 실행은 알리지 않는다. 화면에서 확인한다.
- `disconnected`(설정 안 됨)와 `not_configured`는 이상으로 보지 않는다.
- 합성 자료(`data_origin=synthetic`)가 섞이면 메시지에 "합성 자료 포함"을 붙인다.

## 2. 보내지 않는 것

| 항목 | 처리 |
| --- | --- |
| 프롬프트·응답·요청 ID | 넣지 않는다. 건수와 이유 코드만 보낸다 |
| 토큰·웹훅 주소 | 0600 env 파일에서만 읽고 출력·저장하지 않는다 |
| IP·Pod/노드 이름·파일 경로·실행 파일 경로 | 넣지 않는다 |
| 자유 문자열 | 고정 형식(영문·숫자·`_.:-`, 80자 이하)이 아니면 `OTHER`로 바꾼다 |

## 3. 중복·누락 처리

| 상황 | 처리 |
| --- | --- |
| 첫 실행 | 현재 위치만 기억하고 **과거 기록은 보내지 않는다**. 지금 이상인 상태만 알린다 |
| 같은 시각에 여러 건 | 시각과 키로 구분해 한 번씩만 센다 |
| 관측 목록 50건 초과 | Gateway가 최근 50건만 주므로 "일부만 집계됨"을 붙인다 |
| 웹훅 실패 | 대기열(최대 200건)에 두고 다음 주기에 다시 보낸다. 넘치면 "일부 알림 누락" 알림을 보낸다 |
| 상태 파일이 깨짐 | 현재 위치부터 다시 시작한다(과거 재전송 없음) |
| Gateway 조회 실패 중 | 커서를 움직이지 않는다. 복구 뒤 그 사이의 새 기록을 보낸다(최근 목록 범위 안에서) |

## 4. 켜는 순서 (서버)

1. 웹훅을 만든다(Slack Incoming Webhook 또는 Discord 채널 웹훅).
2. `/etc/serving-runtime/alerts.env`를 만든다. 소유자는 runtime-agent, 권한은 0600이다. 그룹·기타 읽기가 있으면 도구가 실행을 거부한다.
   - `ALERT_WEBHOOK_URL=https://...`
   - Gateway 읽기 API가 보호돼 있으면 `RUNTIME_VIEWER_TOKEN=...`(viewer 역할 토큰)을 넣는다.
3. 먼저 미리보기로 확인한다. 이때는 아무것도 보내지 않는다.
   ```bash
   sudo -u runtime-agent /opt/byul/runtime/.venv/bin/python -B -m tools.alert_notifier \
     --context lab-context --namespace serving --env-file /etc/serving-runtime/alerts.env \
     --state /var/lib/serving-runtime/alert-state.json --label aws-lab
   ```
4. `deploy/agent/serving-runtime-alerts.service.example`에서 context·namespace·label·형식을 바꿔 `serving-runtime-alerts.service`로 설치하고 켠다.
5. 확인한다.
   - 허용되지 않은 모델로 요청 1건을 보낸다. 30초 안에 "Gateway 요청 차단 1건"이 오는지 본다.
   - Tetragon 상태 수집 서비스를 잠시 멈춘다. "Tetragon 상태 수집 이상: stale"과 복구 알림이 오는지 본다.
   - 메시지에 프롬프트·IP·Pod 이름이 없는지 본다.

설치기는 이 서비스를 설치하지 않는다(웹훅 주소가 필요하므로 선택 사항). `--format generic`의 본문 형식은 `runtime-alert/1.0`([내부 기록 형식](내부_기록형식.md))이다.
