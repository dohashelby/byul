## 재사용 분류와 완료 조건

A는 선택 공식 부분시험의 입력·assertion 원형 유지 후보, B는 정상 대조·fixture·계측의 확장, C는 이번 선택 원문에서 직접 대응 시험 미확인. CHK 전체 커버리지·실행 완료율과 구분한다.

최신 재분류는 **A14 · B33 · C30**다. LIF003은 새 media 조기 거부·누적 decoded budget의 보호 assertion을 원형으로 유지할 수 있어 B→A로 바뀌었다. A/B/C는 부분 시험의 재사용 방식이며 신규 개발 개수·실행 완료율·전체 공식 커버리지가 아니다.

제품 작업 상태는 별도 열의 **기존 main 유지 / 기존 확장 / PR34 진행 중 재사용 / 기존 전용 실행기 연결 미확인(이번 비교 범위)**으로 읽는다. 기존 실행기와 진행 중 생산자·수집기를 유지하고 실제 지원 기능의 빈 분기만 추가한다. 공식시험 C의 직접 대응 미확인과 제품 실행기 연결 미확인을 구분한다. 소유자의 최신 작업과 기존 센서를 확인한 뒤 실제 빈 분기만 연결한다.

개발팀은 먼저 endpoint·입력 형식·모델/runner·활성 기능과 정책을 고정한다. 공식 원형 실행과 설치 엔진의 이식 시험을 나누고 commit/node·매개변수·이식 diff·이미지/모델/의존성·실행 ID·원관측 artifact를 남긴다. CPU 표시는 설치/collection 성공을 보장하지 않는다. GPU/custom op/모델/기능 조건 미충족·skip·빈 매개변수·collection 오류는 실제 사유와 미수집 범위로 기록한다.

선정 완결성은 공통확인·적용 분기·필수9결과 범위로 확인한다. 일부 PASS를 전체 PASS로 확대하지 않고, 필요한 미관측은 UNKNOWN, 확인된 독립 FAIL은 유지한다. 실제 적용조건 거짓은 근거와 함께 비적용으로 남긴다.

같은 실험·원관측 artifact는 공유할 수 있다. 각 CHK의 대상·분기·충족/위반·별도 결과를 각각 판정하며, 다른 check_id의 EVD를 검증 없이 복사하지 않는다.

JSON 각 행의 `completion`에 최신 정상 대조·충족·위반·미확인·필수 관측·9개 필수 세부 결과를 담았다. 세부 방법·절차·적용 분기·정책·기여 관계는 같은 해시의 정본 CHK를 `canonical_ref`로 연결한다. 선정 scope→EVD 관측→RES 범위 판정과 전체 자동 완료 집계는 후속 연결이며 이번 문서 동기화의 제품 구현 결과가 아니다.
