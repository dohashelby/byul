# 직접 개발 모듈과 외부 기능 활용 목록

기준일: 2026-10-24 · 근거: 개발계획서 v1.4 §10.3(필수 산출물), §3.2(도입 도구 최소화), D-02

계획서는 Gateway·수집·저장·화면을 **직접 개발 대상**으로 두고, 엔진·통신·행위 통제는 **공식 기능을 활용**하도록 나눈다. 이 문서는 그 경계를 실제 사용 판본과 함께 적는다.

## 1. 직접 개발 모듈

Python 쪽은 모두 Python 3.12 표준 라이브러리만 사용한다(`pyproject.toml`의 `dependencies = []`). 실행 의존성이 없다. Gateway 자체 대시보드와 거기서 쓰던 Chart.js는 2026-10-25 byul 통합 때 제거했다(화면은 byul `platform/`). 빌드 도구·npm·외부 CDN 요청은 없다.

| 영역 | 모듈 | 역할 |
| --- | --- | --- |
| 정책 | `mvp/policy.py`, `mvp/policy_state.py` | 정책 파일 엄격 검증(1.0/1.1/1.2), 기간·철회 판정, 정책 이력 |
| 요청 통제 | `mvp/validator.py`, `mvp/request_flow.py` | 요청 필드·옵션 검증, context 사전 통제, 동시성 |
| 중계 | `mvp/relay.py`, `mvp/engine_client.py`, `mvp/backend.py` | 일반·SSE 중계, 고정 목적지, 추론·metrics 자격정보 분리 |
| HTTP | `mvp/http_handler.py`, `mvp/app.py` | 읽기 deadline·연결 상한, API 분기, 구성·수명주기 |
| 기록·조회 | `mvp/store.py`, `mvp/request_records.py`, `mvp/query.py` | JSONL 기록, 조회 API, 증거 내려받기 |
| 상태 수집 | `mvp/collectors.py`, `mvp/assets.py`, `mvp/revalidation.py` | 엔진 상태·지표·자산 무결성 수집, 재검증 요청 |
| 관측 연동 | `mvp/observation_feed.py`, `mvp/cilium_status.py`, `mvp/lab_report.py`, `enforcement/*.py` | Hubble·Tetragon 이벤트 변환·실시간 수집, Cilium 정책 상태, lab 결과, 정책 후보 생성 |
| 화면 | (제거됨) | 2026-10-25부터 byul `platform/`이 조회 API를 읽어 표시 |
| 시험 전용 | `mvp/mock_engine.py`, `mvp/fake_backend.py` | 모의 엔진·가짜 backend. 실제 엔진이 아님 |
| 도구 | `tools/s3b_cpu_precheck.py`, `tools/k8s_lab_check.py`, `tools/k8s_observation_feed.py` | CPU vLLM 사전 점검, kind lab 점검, 관측 follow |

## 2. 외부 기능·도구

## 3. 직접 개발과 활용의 경계

| 기능 | 공식 기능을 쓰는 부분 | 우리가 만든 부분 |
| --- | --- | --- |
| 엔진 상태·지표 | vLLM 내장 health·`/metrics`·`/tokenize` | 조회 어댑터, 지표 대응표, 수집 상태·미제공 표시 |
| 통신 통제 | Cilium 정책 집행, Hubble 흐름 | 정책 후보 생성, 흐름 변환, 정책 상태 조회, 화면 |
| 행위 통제 | Tetragon TracingPolicy·Override | 규칙 후보 생성, 이벤트 변환, 차단·감시 구분 표시 |
| 요청 통제 | 없음 | Gateway 전체(검증·중계·기록) — 기반 오픈소스(Envoy 등) 선정은 D-02 미확정 |
| 저장·화면 | 없음 | JSONL 저장, 조회 API, 대시보드 |

## 갱신 방법

새 도구를 쓰거나 판본을 바꾸면 이 표를 고친다. 판본은 실행해서 확인한 값만 적고, 라이선스를 직접 확인하면 "재확인 필요" 표시를 지운다.
