# PLT07 최소 Kubernetes 공통 전송 v1

착수 범위는 PLT07의 명시 `all_processes_in_container_uid_netns`·UID/network namespace·TCP connect 한 사건이다. 실제 소비자는 A2의 `boundary_egress` 전용 envelope 소비기이며 아직 새 판본을 소비한 확정본은 없다. 이 문서의 공통 입력 제공, A2 전용 소비, 정식 CheckDef/registry/팩 등록, 실제 실증, 전체5분기는 각각 별도 상태다. 기존 c9 Docker 실행기·정책 형식·sender/receiver/ACK/receipt·판정·다른76정의는 그대로 보존한다. 취득/cache/usage/telemetry·worker-only·DNS/redirect/TLS/proxy를 이 전송으로 해결하지 않는다.

공개 메서드는 `KubernetesHTTP.egress_snapshot(policy_values, *, receiver_target, actor_spec, connect_timeout, total_timeout)`이다. 기존 `REQUEST_BINDING_PROFILE`의 정확 ENV/모델 mapping/소유 engine+probe target으로 transport를 만든다. 하위 capability profile은 `kubernetes-owned-explicit-egress-v1`, 반환 schema는 `guard-kubernetes-egress-snapshot/1`, 고정 helper packet은 `guard-kubernetes-egress-helper/1`이다. 지원은 lab=true/vLLM0.31/CPython3.12 EXAMPLE뿐이며 native0.32/production·실제 worker 신뢰를 열지 않는다. 기존 profile의 HTTP 허용 범위는 바뀌지 않는다.

`policy_values`는 기존11개 이름(subject_scope, subject_container_id, subject_uid, subject_net_namespace_inode, forbidden_receiver_container_id, forbidden_receiver_ip, forbidden_receiver_port, forbidden_protocol, forbidden_operation, validity_start, validity_end)과 새 `source_target_sha256`, `receiver_target_sha256`의 정확13키다. container 신원은 전체 `containerd://`+64hex이고 Docker CID로 자동 치환하지 않는다. scope는 위 all-process 하나, protocol=tcp/operation=tcp_connect 하나, canonical IPv4/1~65535 port, aware 유효 시작<종료다. receiver IP는 아래 소유 target의 실제 Pod IPv4와 같아야 하며 loopback/unspecified/multicast/reserved/broadcast는 거부한다. 관측에서 금지 정책이나 허용값을 생성하지 않는다. 새 Kube CheckDef/POL은 전용 소비 확정 뒤 이 판본에 맞춰 A1이 연결하며 기존 PLT07 원POL을 몰래 완화하지 않는다.

`actor_spec`는 정확 uid/gid/groups이다. UID는 정책과 같고 groups는 명시 정렬·중복 없는 최대16개로 기본값이 없다. source는 기존 IPC context metadata 읽기만 재사용한다. exec helper의 실제 real/effective/saved/filesystem UID/GID·실제 supplementary groups·netns가 입력과 이미 같을 때만 기존 `egress_probe.send_probe`를 호출한다. setuid/setgroups/fork/nsenter를 수행하지 않는다. 불일치는 수집 불완전이며 기업 차단 PASS가 아니다. collector/helper와 실제 serving worker를 구분하며 PID/start/UID/netns/boot/time-domain/capability metadata를 반환한다. 최종 tensor/SDK/worker 소비를 주장하지 않는다.

`receiver_target`은 정확 schema=`guard-kubernetes-egress-receiver-target/1`, environment_ref, source_target_sha256, run_id, lab=true, context, receiver, receiver_pid의8키다. ENV Ref/source target SHA/context/run은 source transport와 같고 `receiver`는 기존 공통 container binding12필드(namespace/namespace_uid/pod/pod_uid/container/container_id/image/image_id/restart_count/node/pod_ip/started_at)의 정확 집합이다. engine/probe와 다른 Pod UID인 이미 소유된 fixture만 받는다. receiver_pid는 명시1~2^31-1이다. API namespace/Pod/container image/restart/start/Ready와 host namespace/shareProcessNamespace 금지 관문을 앞뒤에 확인한다. imageID/API 선언을 노드 이미지·manifest ancestry 인증으로 올리지 않는다.

수신기는 원본 `egress_receiver.py`를 API container `command=[python3,-u,-c,<정확 원본 source>]`, `args=[<명시 port>]`로 이미 실행한 상태여야 한다. 명령을 임의 변경하거나 새 Pod/server/sink를 생성·Start하지 않는다. source/receiver source bytes는 literal pin으로 고정한다. 기존 `_RECEIVER_PROCESS` 읽기만 재사용해 실제 선정 PID/start/UID/netns·command SHA·listener FD socket inode와 startup receipt를 대조한다. 원문 cmdline은 순간 메모리에서만 hash하고 반환/저장하지 않는다. 수신 helper PID와 receiver PID를 구분하며 같은 netns를 확인한다.

순서는 양쪽 세대/소유·정책 유효창 → receiver startup/file identity/process/source 확인 → 세대 재확인 → 한 번의32byte 일회 marker 송신 → 독립 receipt/process 수집 → 양쪽 세대 재확인이다. marker는 반환하지 않고 SHA만 남긴다. 기존 sender의 source time namespace/monotonic cutoff와 connect/marker 시각·ACK 의미를 그대로 사용한다. 부모와 source에서 유효창을 다시 확인하고 source cutoff를 정책 종료와 남은 budget 이내로 제한한다. 서로 다른 노드의 UTC/monotonic/time namespace를 같은 신뢰 시계로 추정하지 않는다. 실제 clock authority/오차는 여전히 미확인이다.

connect_timeout은0<초<=2, 전체 total_timeout은 connect+1<초<=30이며 source/probe/receiver의 모든 API/exec에 동일 남은 전체 예산을 적용한다. 개별 수신 metadata helper는 최대5초다. source SIGALRM은 새 helper만 종료한다. stdin4096bytes, sender/외부 packet65536bytes, 수신 원자료16384bytes·한 행2048bytes·최대9행·기존8접속을 제한한다. 기존 nofollow/regular-file/전후 descriptor/path identity parser를 그대로 재사용하고 더 작은 원천/행 한도를 추가한다. 원문 JSONL/base64는 typed rows·capture/file SHA·fstat metadata로 치환한다. 원문 요청/응답·marker/메시지·비밀/자격hash·Pod env/argv·임의 예외문은 반환/저장하지 않는다.

반환의 receiver_before/sender/receiver_after는 각각 검증된 typed 부분 관측을 보존한다. 뒤 pipe/child reap/수신 수집이 실패해도 앞선 sender와 이미 얻은 receipt를 지우지 않고 가능한 마지막 세대 확인을 계속한다. binding_verified_before_after는 필수 앞뒤 소유 확인에 한정되며 requested_observations_complete는 모든 요청 metadata와 전송/정리가 갖춰졌는지다. ACK timeout/mismatch·후속 clock·첨부 오류와 실제 connect/receipt 판정은 구분한다. 이 공통 계층은 security=UNKNOWN, whole_scope_complete=false, normal attempted=false/succeeded=null을 유지하며 A2의 기존 독립 FAIL predicate를 대신 쓰지 않는다. 거부/timeout·HTTP200을 전체PASS나 정상업무 대조로 바꾸지 않는다.

이번 묶음은 공통 method/schema/source와 명시 CPU EXAMPLE fixture·고정 bytes·오류 범위를 먼저 제공한다. 새 `boundary_egress:kubernetes` 등록은 아직 없다. A2가 기존 forbidden_egress_successes/egress_trials/egress_scope_complete=false와 rule_table을 이 envelope에 연결한 확정 커밋을 전달하면 A1이 최소 wrapper/registry/명시팩·검토 pin·기존 CLI→EVD/RES/RPT→verify→반출/복원·정확Ref 재판정을 마감한다. helper만으로 전체 분기를 완료하지 않는다.
