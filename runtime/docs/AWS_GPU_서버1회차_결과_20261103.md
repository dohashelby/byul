## 발견

### SGLang 길이 한도 차이 (AWS-18 실패 원인)

SGLang v0.5.22은 `--context-length N`이면 내부적으로 요청 길이를 `min(N-1, KV 용량-1)`, 입력 상한을 그보다 5 작게 잡고, 입력이 상한 이상이면 400, 답변은 남은 길이로 조용히 줄인다(소스 `managers/tp_worker.py`, `managers/utils.py`, `managers/scheduler.py`). 결과적으로 입력은 N-7, 입력+답변은 N-2까지만 처리한다. N=2048에서 정책이 허용한 경계 요청(입력 2045+답변 3)이 400으로 거부됐고, 입력 2040+답변 8은 답변이 6으로 잘렸다. 정책보다 더 받아들이는 일은 없어 보안 문제는 아니다. 조치: 엔진 길이에 여유(2112), Gateway의 여유 확인 표시, 배포 시 경계 실측(`e74def0`). 실제 확인은 10번.

## 서버에서 고친 시험 도구 결함

모두 제품(Gateway) 결함이 아니라 시험 도구 결함이었다. 노트북 시험 후 서버에서 재실행해 통과했다(`e1c4b1b`). 그 뒤 Codex 교차 검수 지적을 반영했다(`e74def0`).

| 사례 | 결함 |
| --- | --- |
| preflight | 묶음 폴더 읽기 권한이 없으면 오류로 종료 |
| AWS-12 | 비교 receiver 준비 전 연결, 비교 Pod 삭제 대기 부족 |
| AWS-07 | 대상 상태가 바뀌기 전에 요청 |
| AWS-13 | Gateway가 묶음을 거부했는데 rollout 성공만 보고 '거부 안 됨'으로 오판, sudo 실행 시 복사본 그룹 |
| AWS-17 | 관측 수집 지연, 시간표 시각 정확 일치 요구 |
