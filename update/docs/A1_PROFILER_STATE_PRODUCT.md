# OBS02 profiler 상태 공통 관측 계약

`profiler_observation:kubernetes` / executor0.1.0, collection `kubernetes-profiler-state-observation-v1`, native `vllm-native-lifecycle-metadata/15`와 event `guard-native-profiler/1`이다. 원팩31 OBS02의 SC23-04/05/03·원질문·정상·FAIL/UNKNOWN·독립 backend 기준 및 다른76개 정의 bytes를 보존한 `PACK-KUBERNETES-PROFILER-STATE` DRAFT를 기존 CLI에서 소비한다. 이 단계는 SC23-05의 vLLM adapter/flag 사실이며 전체 OBS02·B LIF14·부모A39 완료가 아니다.

native15는 기존 native8 파일 bytes/hash를 그대로 기반으로 한다. `Worker.profile`, `WorkerProfiler.start/stop/_call_start/_call_stop/step/shutdown`, `TorchProfilerWrapper._start/_stop/_profiler_step`와 실제 등록된 profiler API callback의 call/parent/object, 전후 active/running·제한된 iteration/rank·시각·반환/예외 종류만 수집한다. API 함수의 source/code와 module 함수·등록 endpoint·dependant.call을 함께 확인한다. `profile_prefix`·path·trace·요청/응답 본문·환경변수·임의 예외 원문은 읽거나 저장하지 않는다. 실제 serving/worker hook을 별도 Python 호출로 대신하지 않는다.

공식 고정 소스는 vLLM `db9527a46873454610df6dbedf79a36d6bf1a7f6`이다. `vllm.profiler.wrapper`는 ba71c0accf29b2a987f7afc4dbf5cbe95cb16b72f7a5b67bb95c4b2e7f255fe8, `vllm.v1.worker.gpu_worker`는 43bd01925cd84f7d8a1d4a2ec30e289014a485fe4492a5343cbc893e8ed2f518, `vllm.entrypoints.serve.profile.api_router`는 b943c3a2201134e2d0b38bfa86d00e8b5685f5be6a54f6c7178dee784c1b78e5로 literal 고정한다. 보존된 이미지 layer source와 공식 commit의 원본 bytes 일치를 확인한 자료는 tests/fixtures/profiler-native/PROVENANCE.json이다. 이 일치는 소스 근거이며 실제 backend 실행·수집 증명이 아니다. CPython3.12.3/3.12.14의 observer 코드 계약은 d8c771878b4ed643fed2f773292906f8ef3d2eb4fd029e6df707625ac9e7342b다.

공통 준비는 `guard prepare-lifecycle-sensor --output <새폴더> --profile vllm-native-lifecycle-metadata/15`다. 준비만으로 engine_started/product_connected/image_contents_verified를 올리지 않는다. 기존 소유 session만 seal/capture하고 exact ENV·model repository/revision/inventory/API 별칭·target·engine/probe namespace/Pod/container/image/restart/start·source/code·PID/start/session을 기존 경계에서 확인한다. lab=true/vLLM0.31만 지원하며 native0.32/운영 프로필은 미지원이다. 기존 native8~14·resource probe·framing bytes와 과거 Ref를 보존한다.

POL8은 기존 observation_state_environment_sha256, observation_state_target_sha256, observation_state_validity_start/end, observation_state_required_components와 profiler_prepared_sha256, profiler_backend_kind, profiler_required_ranks다. aware 유효창<=600초, 명시 backend=torch, 중복 없는0~63 rank 문자열 목록과 고정 prepared SHA가 필요하다. 현재 관측 해시·설정·HTTP200에서 승인값이나 상태 의미를 만들지 않는다. source-bound Worker.profile 호출의 rank/객체도 독립 rank membership/worker 집단 인증은 아니다.

정식 제품 전송은 기존 OBS02의 GET health 전후·1token 정상 JSON 전후·8token SSE 첫1byte 소유client 종료만 재사용한다. 이 실행기는 `/start_profile`·`/stop_profile` 요청을 보내거나 profiler/worker/Pod·backend·Secret·설정·등록을 변경하지 않는다. 실제 profiler start/stop·실패 주입·trace callback·산출/전송·다음 시작 시험은 B가 backend/route 접근/정상/실패/출력·정책을 구체화한 뒤 별도로 시행한다. 미확정 payload/binding은 지원 계약이 아니다.

같은 recording/PID/start/source의 유일 call/parent와 wrapper 객체 및 포함된 시간 구간으로 vLLM adapter와 flag를 대조한다. WorkerProfiler._call_stop은 하위 _stop 예외 뒤에도 running=false로 바꾼다. TorchProfilerWrapper._stop은 torch stop 뒤 table·출력 처리도 수행하므로 adapter RAISE가 곧 실제 backend stop 실패라는 뜻도 아니다. `profiler_conflict_candidates`는 이 둘의 차이를 남기며 actual_backend_stop_failed/actual_collection_continued/trace_output_complete/cross_process_API_worker_link/confirmed_full_state_violation은 false다. 다른 PID·같은 hash·가까운 시각으로 API-RPC-worker를 합치지 않는다.

`profiler_native_samples`, `profiler_worker_calls`, `profiler_rank_status`, `profiler_conflict_candidates`, `profiler_missing`과 backend_collection_stopped/trace_output_completed/cross_process_rpc/scope_complete=false를 기록한다. 원래 state_* 관측과 함께 모든 판정축 UNKNOWN·normal_control.succeeded=null을 유지한다. source/객체·필수rank·call pair·정리/교체/restart·후속 수집/seal/첨부 오류는 미확인 또는 ABORTED이며 앞선 정제 관측과 독립 FAIL을 지우지 않는다. 단위 helper나 등록만으로 분기를 완료하지 않는다.

구현·회귀·문서 초안 단계이며 아직 고정 검증·설치본·확정PR·실제 환경 검증을 주장하지 않는다.
