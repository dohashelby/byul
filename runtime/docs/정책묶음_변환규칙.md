# 플랫폼 CONFIRMED 정책 → 런타임 묶음 변환 규칙

근거: `contracts/schemas/policy.schema.json`, `contracts/README.md`, `src/serving_runtime/mvp/policy_bundle.py`. `byul-policy/0.1` 원본 전체와 **독립적으로 기록한 정규 JSON SHA-256**을 입력한다. 정규 JSON은 키 정렬·공백 없는 UTF-8이다. `platform-approval.aws-lab.json`은 원본이 아닌 요약본이라 입력할 수 없다. `DRAFT`와 해시 불일치는 거부한다. 계약 자체는 DRAFT이며 이 변환은 LAB 도구다.

| 플랫폼 원본 | 런타임 역할·필드 | 규칙 |
| --- | --- | --- |
| `policy_id`, `policy_version`, `target_ref` | `runtime-mvp/1.1` 또는 `1.2`의 `policy_id`, `policy_version`, `target_id`; bundle `policy_ref`, `target_ref` | 값 그대로. `target.target_id`도 같은 ID여야 한다. |
| `validity.valid_from`, `valid_until` | Gateway 같은 이름, bundle `validity`; 승인 목록의 `valid_until` | 시각대 포함 원문. null은 목록에서 생략. |
| `approval.approval_ref`, `approved_at`, `approved_by` | Gateway `approval_ref`; `runtime-policy-approvals/1.0` 항목의 `approval_ref`·`approved_at`; bundle `approval` | 승인 기록의 자기 신고 사본. `approved_at`의 `Z`만 `+00:00`으로 직렬화한다. **승인 행위 검증이 아니다.** |
| `runtime.gateway` 공통 필드 | Gateway `allowed_models`, `output_default_tokens`, `output_max_tokens`, `max_body_bytes`, 선택 `max_context_tokens` | 그대로. Gateway 로더로 다시 검증한다. |
| `runtime.gateway.profile`, `max_n`, `extra_fields` | Gateway 1.2 같은 이름 | 1.1 선택 시 해당 필드가 있으면 거부. 1.2 `cache_isolation`은 필수 서버 값(`off` 또는 `per_principal`)에서 가져온다. |
| `runtime.enforcement` | `runtime-enforcement-intent/1.1` | null이면 서버 intent 원본을 쓴다. 값이 있으면 서버 intent와 정규 JSON 및 schema가 정확히 같아야 한다. |
| `runtime.exec_exceptions` | `runtime-exec-exceptions/1.0` | 현재 빌더는 비어 있지 않으면 거부한다. 예외를 누락해 묶지 않는다. |
| 플랫폼 정책 전체 | bundle `policy_ref.sha256` | 원본 전체의 정규 JSON 해시. Gateway 파일 바이트 해시와 다르다. |
| 생성한 Gateway 파일 | 승인 목록 `entries[0].sha256`, bundle `files[].sha256` | 실제 파일 바이트의 SHA-256. `files[].bytes`도 실제 바이트 수. |
| 서버 값 파일 `target` | `runtime-target/1.0` | 엔진 kind·image digest·모델·Kubernetes context/namespace/selector/container 등 **서버에서 확인한 값**. `target_id`는 원본 `target_ref`와 일치. |
| 서버 intent 원본 | `enforcement_intent` 역할 | 서버의 namespace·엔진·image digest와 target을 대조한다. `REPLACE` 자리값은 거부. |

## 서버 값 파일

`runtime-bundle-server-values/1.0` JSON 객체의 필수 키는 `schema_version`, `gateway_schema_version`(`runtime-mvp/1.1` 또는 `1.2`), `target`(`runtime-target/1.0` 문서 전체)다. 1.2에서는 `gateway_cache_isolation`(`off` 또는 `per_principal`)도 필수다. 엔진 image digest는 `sha256:<64자리 소문자 hex>`여야 한다. 모델 ID는 Gateway 허용 모델에 있어야 한다. 서버마다 실제 digest·target·intent의 `REPLACE` 값을 확인해 채운 **서버 사본**을 입력한다. 엔진 image digest, intent 서버 값, target 세부를 플랫폼 정책에서 추정하지 않는다.

## 거부·미변환 목록

- 원본이 `byul-policy/0.1` 전체가 아니거나 `CONFIRMED`가 아니거나, 외부에서 받은 정규 해시가 다르면 거부한다. 해시만 맞는다고 승인 진위가 검증되지는 않는다.
- `runtime.gateway`의 지원되지 않는/모호한 필드, 1.1에 1.2 전용 필드, 1.2의 cache isolation 서버 값 누락, 비어 있지 않은 `exec_exceptions`, 플랫폼 enforcement와 서버 intent 불일치, target/intent의 엔진·image digest·namespace 불일치는 거부한다.
- `verification`, `environment_ref`, 선택 `framework_values`는 Gateway 집행값으로 추측 변환하지 않는다. 원본 정규 해시에만 들어간다. `data_origin`도 Gateway 정책 필드가 아니다.
- bundle verifier는 묶음 구조·해시를 검사한다. `approval.py`의 LAB 검증기는 승인 목록과 Gateway 정책 바이트 해시를 대조하며 서명·플랫폼 승인 검증이 아니다. 실제 엔진·Kubernetes 배치·Cilium/Tetragon 집행은 별도 대조가 필요하다.

## LAB 골든 시험의 출처 한계

`deploy/gpu-lab/platform-approval.aws-lab.json`은 원본이 아니라 요약본이다. 원본의 기록 해시는 `b37fa34fee6fa68b53a15ab0d01c614c993f5b93db45fd35ebb040f6c739a48f`이고 저장소에 원본 전체가 없어 재계산할 수 없다. 시험은 요약에서 재구성한 **합성 EXAMPLE** 정책(정규 해시 `e6ff3f32b1e4f94d28ecd8c53e5ac420f058cea9be50cd6aafa042c7ae520cef`)과 `tests/fixtures/bundle-server-{vllm,sglang}.json`의 가짜 digest를 쓴다. intent의 `REPLACE` 두 값도 시험 사본에서만 채운다. 두 엔진 모두 `bundle verify`를 통과했고 Gateway 정책 바이트는 기존 LAB 파일과 동일했다(파일 SHA-256 `472a7ccabe769f6d2eb3f961ffe41aab320e4138bd9a0e7262f69c6396f2f1dc`). 따라서 기존 LAB 승인 목록 항목의 바이트 해시는 유지된다. **원본 플랫폼 판본 해시 일치 시험은 불가능했다.** 합성 정책의 `policy_ref.sha256`을 실제 원본 값으로 사용해서는 안 된다.
