# BYUL 실증 크레딧 중단

`tools.aws_credit_guard`는 전용 실행 역할과 정확한 `byul:credit-guard` 태그가 있는 새 실증 자원만 제어한다. AWS 계정 전체의 결제 상한이 아니며 root·다른 역할·다른 서비스의 지출은 차단하지 못한다. 크레딧 API는 청구 지연이 있으므로 잔액 0까지 쓰지 않는다. 최신 잔액·원 청구 반영 여부를 별도로 확인한다.

## 실행 조건

- 잔액은 `FreeTier.GetAccountPlanState`의 ACTIVE·동일 계정·USD 값으로 확인한다. 잔액 $5 이하, 조회 실패, 소유 자원 조회 실패·설정 불일치는 영구 중단 정책을 건다. 신용이 회복되어도 자동 해제하지 않는다.
- EventBridge가 1분마다 Lambda를 실행한다. 정상일 때만 전용 실행 역할의 3분 이내 IAM 허용 기한을 갱신한다. 감시가 중단되면 새 유료 작업은 만료된 IAM 명시적 Deny에 걸린다. IAM 전파·예약 실행·종료는 지연될 수 있다.
- 세션 최대 $6·45분 이하로 배포한다. 고정한 시간당 상한과 별도 세션 준비금으로 경과 비용을 산정하고, 활성 세션 예약액 합계가 잔액에서 $5를 뺀 금액을 넘으면 중단한다. API 잔액이 갱신되지 않아도 세션 기한/산정 비용으로 종료한다.
- 실행은 전용 역할을 사용한다. EC2 생성은 지정 리전·AMI·서브넷·인스턴스 유형, 암호화 디스크 200GiB 이하로 제한한다. instance/volume/security-group에는 동일 guard 태그와 `byul:ephemeral=true`, UTC `byul:deadline`, `byul:budget-usd`를 생성 시 붙인다. 디스크 `DeleteOnTermination=true`, 인스턴스 종료 동작 terminate, 별도의 노드 자체 종료 예약도 요구한다. 실행 역할에는 태그 재작성·새 스냅샷·임의 디스크 생성 권한을 주지 않는다.
- 종료 대상은 정확한 guard 태그의 소유 세션이다. 디스크 삭제는 동일 guard+ephemeral 태그·available·미연결일 때만 한다. 사용자/연결 디스크와 다른 guard의 자원은 삭제하지 않는다.
- 감시 자체도 배포 시 최대 24시간 기한을 가진다. 기한이 지나면 역할을 차단하고 소유 자원 정리 후 스케줄을 끈다. 별도 비용 승인 없는 재활성화·기간 연장은 하지 않는다. Lambda와 로그/예약 호출 자체도 AWS 요금 대상일 수 있다.

## 배포와 확인

기존 인증 프로필을 사용해 `python -m tools.aws_credit_guard_deploy --config <JSON> --aws-binary <CLI> --profile <PROFILE> --output <EXTERNAL_DIRECTORY>`로 배포한다. 설정은 코드의 `validate_config` 및 `execution_policy`가 요구하는 guard와 infrastructure 두 객체다. 실제 계정 ID·리소스 ID·인증 캐시는 저장소 밖에 둔다. 액세스 키를 생성하거나 파일에 저장하지 않는다. 런타임 Boto3는 Lambda 기본 SDK를 사용한다.

배포 결과만으로 실제 종료 검증을 주장하지 않는다. 전용 역할로 저비용 CPU canary 한 대를 만들고 짧은 기한을 부여한 다음, 직접 종료 API를 보내지 않고 예약 감시가 종료·디스크/보안그룹 삭제를 수행했는지 확인한다. 크레딧 소진 분기는 실제 잔액을 소비하지 않고 모의 실패 시험으로 검증한다. GPU 실행·생산자 자격·69개 판정은 별도 증거가 필요하다.

재개 전에는 SSM 상태의 최신 시각·`blocked=false`·미만료 허용 기한, 활성 자원·예약 비용·새 크레딧과 정확한 역할을 확인한다. 래치된 중단 정책을 자동으로 지우지 않는다. 사용자 승인 범위와 실제 잔액을 확인한 운영자가 원인을 해결하고 명시적으로 재배포해야 한다.
