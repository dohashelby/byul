# 두 판본 J01·J02 입력·시간·비용 계획

2026-11-13 작성. 단독 개발자의 M-A7 계획이며 실행 승인이나 실측 결과가 아니다. 판본·GPU 이미지는 작업지시서 0.1절만 따른다. 기준은 사용자 결정 14에 따라 V0 기본을 유지한다. 계획의 정본 팩은 #257의 @34이며 main 병합은 별도 승인 대상이다.

69개 점검별 두 쪽의 ENV·target·prepared·정책 포인터, 필요한 정책 키와 예상 공백은 [입력 계획 JSON](ma7-session-input-plan.json)에 있다. 69개 = M-A 27개 + M-B 42개, J01 6개 + J02 63개다. 퇴역 점검 8개는 포함하지 않는다. 실제 클러스터 입력이 없어 현재 138쪽의 포인터는 모두 `null`이고 사유를 적었다. 구조 검증과 실제 입력 사전 점검을 구분하며 `ready_for_execution=false`, `input_preflight_passed=false`다.

## 입력 조립과 남은 것

| M-A 분류 | 점검 | 사용할 입력·남은 것 |
|---|---|---|
| 이전 lab 경로 8개 | REQ-01·11·15·18·19·20, OBS-04·09 | 기존 실행기·정책 틀을 재사용하되 새 ENV/target/prepared·세션·판본별 소스 자격을 다시 결합한다. 과거 EVD/RES를 새 결과로 옮기지 않는다. OBS-09 기업 수집기 범위는 제외 사유를 남긴다. |
| 확정 값 5개 | REQ-03·13·17, OBS-05, LIF-13 | #257의 확정 값은 JSON에도 복사해 출처를 명시했다. 정책 CONFIRMED·정식 승인자를 만들어내지 않는다. LIF-13 역할·승인 세대·fallback은 실제 집행 근거가 없으면 UNKNOWN이다. |
| 1차 제외 8개 | REQ-02, OBS-01·06·11, PLT-07·10·11·12 | 정본 경로를 실행한 뒤 입력 부재·제외 범위와 UNKNOWN을 기록한다. 실행 전 예상 상태를 RES로 만들지 않는다. |
| TP2 3개 | REQ-14·16·21 | `gpu_a_run_inputs`의 사례 생성·`gpu_a_aws_lab` 렌더를 쓴다. 새 두 판본 설치 파일 자격·실제 GPU/Pod·rank/세션 결합은 남았다. REQ-16의 Qwen2-VL-2B-Instruct snapshot은 아직 미고정이다. |
| 대상 비적용 2개 | REQ-04·06 | 기존 사용자 결정과 실제 Gateway 설정의 비적용 근거를 정본 선정에 남긴다. 기능 부재 판정의 새 승인이 아니다. |
| SUP-08 1개 | SUP-08 | #257의 `tools.mvp_sup08_inputs`를 사용한다. 고정 Phi-3 Vision 파생 fixture와 실제 ENV/target이 없어 최종 조립은 남았다. 과거 ignored→consumed는 예상 회귀 근거이며 새 비교 RPT는 J02에서 만든다. |

M-B 입력 42개는 빈 포인터와 원인을 남겼다. J01의 LIF-08·11·SUP-06은 `tools.b12_tp2_inputs`의 정상→장애→복구 순서와 정책 기한을 사용한다. 기존 도구가 만든 선언 포인터를 실제 파일 검증 완료로 해석하지 않는다. 이틀 범위 뒤 M-B1·M-B4부터 연결한다.

입력 사전 점검은 다음을 모두 확인한 뒤에만 통과로 바꾼다.

1. @34 병합 상태와 실제 팩 Ref·정책 scope·정책 출처·최종 커밋을 고정한다.
2. 판본 표의 정확 이미지, 실제 설치 판본·Python·관측 소스/함수, 같은 GPU 모델·드라이버·GPU 수·TP/PP/DP와 모델 snapshot·inventory를 확인한다.
3. 실제 namespace UID·Pod UID·container ID·restart·PID/start·rank, target canonical SHA·prepared SHA·session을 결합한다. 재기동 뒤 새 세대는 다시 결합한다.
4. 정상/위반/누락/복구 사례, 정책 기한, 독립 정상 대조와 종료·회수 절차를 확인한다. source 변경·미등록 생산자·관측 공백은 PASS 근거로 쓰지 않는다.
5. 기존 `guard select` 결과가 의도한 scope와 일치하는지 보고 비용 승인 뒤 실행한다. 자리표시자·EXAMPLE ENV로 사전 점검을 통과시켰다고 기록하지 않는다.

| J01 | 승인된 이미지·모델 준비, GPU/토폴로지·P2P 기록 | 30~60분 | 모델 snapshot 미고정·다운로드 미승인·단가 미확인은 미준비다. |

| J01 | 회수 후 같은 조건의 후보에서 같은 순서 | 80~105분 | 기준 증거·prepared를 후보에 복사하지 않는다. |

| J02, 단일 L4 | 공통 사전 점검·정책/모델 입력 고정 | 20~30분 | M-B2~B6 입력과 SUP-08 fixture가 없으면 승인 요청 전 계획을 수정한다. |

| J02 | 같은 조건의 후보에서 같은 63개 실행 | 120~180분 | `guard update`의 제품 경로를 사용한다. J01 6개는 이 세션 scope에서 구분한다. |
| J02 | 정확 Ref·비교 RPT·원자료 반출 SHA·정리·stopped | 20~30분 | 재기동 여유를 포함해 총 5~7.5시간을 가정한다. J03 공식 재판정은 별도다. |

L4의 TP2 실행에 custom all-reduce/P2P가 없으면 REQ-21의 관련 관측은 UNKNOWN일 수 있다. 이는 기동 성공과 다른 조건이다. g6.12xlarge는 물리 GPU 4장 중 2장만 할당해도 인스턴스 전체 비용이 든다. [AWS 공식 G6 사양](https://aws.amazon.com/ec2/instance-types/g6/)과 [인스턴스 사양표](https://docs.aws.amazon.com/ec2/latest/instancetypes/ac.html)를 확인했다. 실제 계정의 현재 할당량·인스턴스 상태는 조회하지 않았다.

J01 단가는 [과거 TP2 계획](tp2-run-plan.md)의 2026-11-06 콘솔 값, J02는 [비용 장부](../gpu-a/COST_LEDGER.md)의 2026-11-05 콘솔 값이다. 최신 단가를 확인한 견적이 아니다. AWS [온디맨드 요금 안내](https://aws.amazon.com/ec2/pricing/on-demand/)를 확인했으나 이 문서에 최신 지역 단가를 검증했다고 표시하지 않는다. 실행 승인 요청 때 실제 지역·OS·테넌시·시간당 단가를 재확인하고 계산을 갱신한다.

EBS·스냅샷 보존, 전송·공인 IPv4, 세금·환율은 위 EC2 합계에 포함하지 않았다. 기존 300 GiB EBS의 지속 비용도 별도다. 현 저장소에서 실제 볼륨 상태를 조회하거나 삭제하지 않았다. 과거 $20 승인은 한 판본 기준이므로 이번 두 판본 실행을 승인하지 않는다. 결정 1·6의 새 상한, 추가 이미지/모델 다운로드 범위, 현재 할당량·정리 절차를 승인받기 전 비용 발생 동작을 하지 않는다.

## 예상 공백과 완료 상태

기준 V0의 내부 관측(D1~D3), 기준 Python 패치 자격, 후보의 이미지 설치 bytes 대조·GPU 생산자 등록, M-B4 고정값이 남았다. 결정 9 여섯 항목은 항목별 검토 대기다. D4·D5는 기존 결정 10 범위의 공백을 유지한다. 관측 공백 수를 실측 성공 수로 세지 않으며 현재 자료만으로 최종 비교 가능 점검 수를 확정하지 않는다.

계획·69행 구조 검증은 끝났고 실제 입력 사전 점검은 미완료다. M-A7 전체 완료를 선언하지 않는다. 승인 없이 GPU·클라우드·이미지/모델 다운로드·공식 재판정은 실행하지 않았다.
