### 플랫폼 자료 변경(LAB)

확정 정책 `aws-lab-policy-001` r2가 엔진 종류·이미지 digest·Gateway 스키마·엔진 컨테이너·intent가 비어 있는 환경 r1을 고정 참조해 내보내기가 `BUNDLE_FIELDS_MISSING`으로 거부됐다. 서버 값을 채운 환경 r2(엔진 `vllm`, digest `sha256:c1c9f6fd…`, `runtime-mvp/1.1`, 컨테이너 `engine`, TG-SECRET-01 monitor·enforce 허용 intent)를 저장하고, 정책을 r2 참조로 저장(r3)한 뒤 확정(r4, runtime 담당 자기 신고 승인)했다. 정책 본문은 r2와 같고 `environment_ref`만 다르다.

## 새로 찾은 문제

| 문제 | 원인 | 처리 |
| --- | --- | --- |
| 상태 파일이 `0664`로 생겨 에이전트·모니터 생성기가 신뢰하지 않음 | Ubuntu `pam_umask`(USERGROUPS_ENAB)가 사용자명=그룹명 계정에 umask 002를 적용. `sudo -u runtime-agent`로 실행한 수집기의 파일이 그룹 쓰기 권한을 가짐. 이전 실행이 남긴 `.next` 임시 파일은 권한이 유지됨 | 서버: 계정 안에서 `umask 022` 후 실행. 코드: 명시 권한으로 쓰도록 수정(이 회차 뒤) |

운영 메모: `ps`의 사용자 칸이 `runtime+`로 잘려 이름 조건으로 프로세스를 고르지 못한 일이 있었다. `ps -o user:20`처럼 폭을 지정한다.
